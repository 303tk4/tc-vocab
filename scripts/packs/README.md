# 単語パッケージの作成スクリプト

仕様書 16.5「単語パッケージ」の「TOCFL・HSK の単語集の作り方」に従い、`public/packs/` に単語パッケージを出力する。TBCL 詞語表の第1〜7級を、TOCFL の級に合わせて5つのパッケージに分ける。

| ID        | TBCL の級 | TOCFL の級の目安           | 語数  | 状態     |
| --------- | --------- | -------------------------- | ----- | -------- |
| `tocfl-1` | 第1〜3級  | 準備級〜基礎級（〜A2）     | 1,375 | 公開     |
| `tocfl-2` | 第4級     | 進階級（B1）               | 1,496 | 作成済み |
| `tocfl-3` | 第5級     | 高階級（B2）               | 2,735 | 作成済み |
| `tocfl-4` | 第6級     | 高階級（B2）〜流利級（C1） | 4,222 | 作成済み |
| `tocfl-5` | 第7級     | 流利級（C1）〜精通級（C2） | 5,006 | 作成済み |

意味の言語ごとに別の単語集とする（仕様書 16.5「意味の言語」）。上の表は日本語版。英語版は `tocfl-1-en` のように ID に `-en` を付け、語・読み・タグは日本語版と同じにする。名前には「【意味：英語】」などを添える（アプリが `meaningLanguage` を示すようになるまで、一覧で区別できるようにするため）。

| 英語版                     | 状態               |
| -------------------------- | ------------------ |
| `tocfl-1-en`〜`tocfl-3-en` | 作成済み           |
| `tocfl-4-en`・`tocfl-5-en` | 意味の下書きがまだ |

```bash
# 1. 辞書のデータを入手する（下の「元データ」。リポジトリには入れていない）
# 2. パッケージを作る（意味の表 meanings/<区分>.<言語>.tsv があるものをすべて
#    public/packs/<id>.json・index.json と reports/<id>-readings.md に出力）
node scripts/packs/build-tocfl.mjs
node scripts/packs/build-tocfl.mjs --pack tocfl-2   # 1つだけ作る

# 意味が未記入の語の一覧を書き出す（意味の下書き用）
node scripts/packs/build-tocfl.mjs --pack tocfl-3 --worklist 一覧.tsv
# 英語版では、日本語版の意味を手がかりとして各行の末尾に添える
node scripts/packs/build-tocfl.mjs --pack tocfl-2-en --worklist 一覧.tsv

# 読みの確認リストだけ作る（意味の下書きの前に読みを確かめる）
node scripts/packs/build-tocfl.mjs --readings-only --pack tocfl-3

# 変換処理の単体テスト（Node.js 標準のテストランナー。依存パッケージは使わない）
node --test scripts/packs/
```

## 構成

| パス                             | 内容                                                                   |
| -------------------------------- | ---------------------------------------------------------------------- |
| `build-tocfl.mjs`                | TOCFL パッケージを作るスクリプト。パッケージの版・更新日もここで決める |
| `tocfl-guide.mjs`                | TOCFL と TBCL の級の対応表、index.json の名前・説明・出典              |
| `lib/xlsx.mjs`                   | xlsx（zip）の読み取り。依存パッケージを増やさないため自前で行う        |
| `lib/zhuyin.mjs`                 | 注音の正規化と、注音 → 拼音の変換                                      |
| `lib/tbcl.mjs`                   | TBCL 詞語表の読み取り                                                  |
| `lib/reading.mjs`                | 繁体字から注音を決める（辞書と詞語表の照合）                           |
| `lib/pack.mjs`・`lib/output.mjs` | パッケージの組み立てと出力の整形                                       |
| `lib/*.test.mjs`                 | 単体テスト（`node --test scripts/packs/`）                             |
| `meanings/<区分>.<言語>.tsv`     | 意味（AI による下書き）。`ja`・`en`。`TBCL の id<TAB>繁体字<TAB>意味`  |
| `reports/<id>-readings.md`       | 生成物。辞書と詞語表の読みが完全には一致しなかった語の一覧（確認用）   |
| `sources/`                       | 元データ（下表）                                                       |

### ライセンス

- **詞語表**：國教院のサイトにライセンスの表示は見当たらない。「公式の語彙表は公開されており、単語集として配ってよいものとして進める」（仕様書 16.5 の決定）に従う。
- **辞書**：創用CC 姓名標示-禁止改作 3.0 臺灣。使うのは見出し語と注音だけで、注音は書き換えない（空白と軽声の記号の位置をそろえるだけ）。拼音は注音から変換する（辞書の拼音は使わない。仕様書 16.4）。姓名標示は使用說明の指定どおり、`index.json` の `source`（と `sources[].attribution`）に書いている。

### TOCFL の「華語八千詞」を使わない理由

TOCFL の〈華語八千詞表〉は、國家華語測驗推動工作委員會が 2021 年 6 月 30 日で提供をやめた。現在の TOCFL は國教院の「臺灣華語文能力基準」（TBCL）を出題の参考にしているため、その詞語表を使う（利用者の承認済み）。

## 読みの決め方（`lib/reading.mjs`）

教育部《重編國語辭典修訂本》の注音を正とし、詞語表の注音は候補を選ぶ手がかりに使う。

0. 詞語表の読みを整える。第7級などには音節の間の空白が抜けた読み（「ㄐㄧㄚˇㄕㄨㄛ」）があるため、声調記号の後ろと軽声の「˙」の前で区切り、それでも音節にならない部分は成り立つ音節に分ける。見出しの「沒(有)用」「有助（於）」のような省略できる部分は、省いた形と含めた形の2語にする。
1. 辞書の候補を集める。語が辞書になければ、最長一致で区切った組み合わせを候補にする。`台→臺`、`裏→裡`、`唇→脣`（辞書の「唇」は ㄓㄣ の見出しで、くちびるは「脣」）、`癡→痴`、`舖→鋪`、`樑→梁`、`勳→勛`、`艷→豔` のように辞書で別の字体の見出しになっている字は置き換えて引く。「哪兒」のような儿化の語は、「哪」の読みに「ㄦ」を付けた読みも候補にする。
2. 詞語表の読みと一致する候補があれば、それを使う（多音字の読み分けもこれで決まる）。
3. 表記の流儀の違い（「一」「不」の変調、片方が軽声）だけで一致すれば、辞書の表記を使う。
4. 辞書に語として載っていて読みが1つで、詞語表の読みが欠けていれば、辞書の読みを使う。
5. 辞書と詞語表からは決められない語は、`build-tocfl.mjs` の `READING_FIXES` で読みを指定する（例：有助於。詞語表の見出し「有助（於）」に「於」の読みがない）。
6. それ以外は `要確認:読み` タグを付ける（tocfl-1 で 8 語、tocfl-2 で 10 語、tocfl-3 で 11 語、tocfl-4 で 4 語、tocfl-5 で 26 語）。多くは「熟」（ㄕㄨˊ／ㄕㄡˊ）や「場」（ㄔㄤˊ／ㄔㄤˇ）のように、辞書と詞語表で採る読みが異なる語。

判定の結果は `reports/<id>-readings.md` で確認できる。

## TOCFL と TBCL の級の対応

國家華語測驗推動工作委員會の[答客問](https://tocfl.edu.tw/assets/files/announcement/TOCFLandTBCL.pdf)の対応図による。TOCFL の入門級（A1）は TBCL の 2+級、基礎級（A2）は 3+級、進階級（B1）は第4級、高階級（B2）は第5〜6級にあたる（聴力・閲読とも）。流利級（C1）は聴力が第6級・閲読が第6〜7級、精通級（C2）は第7級にあたる。

単語には、その語が初めて必要になる TOCFL の級のタグを付ける。第6級の語は高階級で、第7級の語は流利級の閲読で必要になるため、それぞれ `TOCFL:高階`・`TOCFL:流利` とする。精通級のタグはない（新しく加わる語がないため）。

### 詞語表の「*」の級

詞語表の「第1*級」〜「第4*級」の「*」は、**同じ級の中で難度が相対的に高い語**の印である。國家教育研究院《華語文能力基準應用參考指引使用手冊精華版》（2024年7月、ISBN 9786263455337）の「分級詞語分佈與數量」（25ページ）に、教材の編集や評価に使いやすいよう第1〜4級の各級の中の難易度をさらに分け、「難度相對較高的詞語以*字號標示」とある。たとえば第1級 396 語は「1」182 語と「1*」214 語に分かれる。

この手引きは「*」と TOCFL の対応図の「+」（2+級など）の関係には触れていない。このパッケージでは、入門級（2+）までに第2*級の語が、基礎級（3+）までに第3*級の語が必要になるものとして、TOCFL の級の目安のタグを付けている（推定）。

**単語のタグでは「\*」を区別しない**（利用者の決定。「1級」と「1*級」の違いがわかりにくいため）。第1*級の語も `TBCL:1級` にする。級の判定や重複の整理（下の「意味の下書き」）では、`*` の級を区別したまま扱う。

| TBCL 詞語表の級 | タグ                              |
| --------------- | --------------------------------- |
| 第1級・第1*級   | `TOCFL`、`TOCFL:入門`、`TBCL:1級` |
| 第2級・第2*級   | `TOCFL`、`TOCFL:入門`、`TBCL:2級` |
| 第3級・第3*級   | `TOCFL`、`TOCFL:基礎`、`TBCL:3級` |
| 第4級・第4*級   | `TOCFL`、`TOCFL:進階`、`TBCL:4級` |
| 第5級           | `TOCFL`、`TOCFL:高階`、`TBCL:5級` |
| 第6級           | `TOCFL`、`TOCFL:高階`、`TBCL:6級` |
| 第7級           | `TOCFL`、`TOCFL:流利`、`TBCL:7級` |

## 意味の下書き

`meanings/<区分>.<言語>.tsv` は AI（Claude）による下書き。英語版は日本語版の意味を参考にしつつ、繁体字と読みから直接書いた。パッケージの説明（`index.json` の `description`・`meaningNote`）にそのことを書いている。見出しが「爸爸/爸」のような語は別々の単語にし、同じ繁体字・同じ拼音の語（仕様書 6.1 の重複）は級の低いほうだけを残す。

## 仕様書への追記が必要な点（メモ）

仕様書は M4 のセッションが編集中のため、ここに記録しておく。

1. **16.5 の語彙表の出典**：「TOCFL 華語八千詞」は提供が終わったため、國教院「臺灣華語文能力基準」詞語表に改める。タグの例も `TOCFL`・`TOCFL:入門`・`TBCL:1級` などに合わせる。
2. **index.json の追加の項目**：仕様書 16.5（版 1.12）の形式（`id`〜`source`）に合わせて出力している。そのほかに、`updatedAt`・`meaningNote`・`tagCounts`（単語ごとのタグの語数）・`levelGuide`（級の対応表。3言語）・`sources`（出典ごとの URL・ライセンス・姓名標示）を追加の項目として出力している。仕様書に載せるか決める。
3. **単語パッケージの画面（利用者の要望）**：パッケージを選ぶ画面で「TOCFL 対応」であることがわかるように示し、選んだパッケージの見本やインポートのプレビューで、`levelGuide` の対応表（TOCFL のどの級が TBCL のどの級にあたるか）を表示する。
4. **出典の表示**：辞書の姓名標示は使用說明の指定の書式（`source`、`sources[].attribution`）で示す。使用說明は「再配布時に完全に保持すること」を求めているため、表示か同梱の方法を決める。
5. **一・不の変調**：パッケージの注音・拼音は辞書に合わせて本来の声調で書く（例：一起 yī qǐ）。利用者が変調後の拼音（yì qǐ）で登録した単語とは、6.1 の判定で重複とみなされない。
6. **テストの実行**：`node --test scripts/packs/` は `npm test` と CI に入っていない。`package.json` の `test` に加えるか、CI に手順を足す（`package.json` は M4 のセッションが変更中のため保留）。
7. **16.4 段階2 との関係**：`lib/zhuyin.mjs`（注音 → 拼音）と `lib/reading.mjs`（辞書による読みの決定）は、アプリの「読みを付ける」機能や `public/dict/zhuyin.json` の作成にも流用できる。
