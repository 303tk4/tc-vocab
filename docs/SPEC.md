## 1. 目的と範囲

### 1.1 目的
繁体中文（台湾華語）の単語を、PC・タブレット・スマートフォンで学習できるブラウザアプリを提供する。

### 1.2 基本方針
- サーバーを持たない。データはすべて利用者の端末内（IndexedDB）に保存する。
- PWA としてインストールでき、オフラインで動作する。
- 学習モードはプラグイン式とし、コアを変更せずに追加できるようにする。

### 1.3 v1.0 の範囲
| 区分 | 内容 |
|---|---|
| 対象 | 初期画面（モード選択）、暗記カードモード、単語データ画面（一覧・インポート・エクスポート）、設定画面、サンプル単語、PWA、GitHub Pages での公開 |
| 対象外 | クイズモード、漢字なぞりモード、画面上での単語の個別追加・編集、統計画面、端末間同期、アカウント機能 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 単語 | 学習の最小単位。繁体字・注音・拼音・意味・例文・タグを持つ（[6.1](#61-単語-word)） |
| タグ | 単語に付けるラベル。単語リスト（単語帳）の役割も兼ねる |
| 学習モード | 単語を学習する方法（暗記カード、クイズなど）。プラグインとして実装する |
| セッション | 学習モードの開始から結果表示までの1回分の学習 |
| SRS | 間隔反復（Spaced Repetition System）。記憶の定着度に応じて次の出題日を決める仕組み |
| 復習期限 | SRS が算出した、その単語を次に出題すべき日時 |
| 新規カード | そのモードでまだ一度も学習していない単語 |

### 4.5 SC-04 単語データ
| ID | 要件 |
|---|---|
| FR-WORDS-01 | 単語を一覧表示する（繁体字・注音・拼音・意味・タグ）。件数が多い場合は仮想スクロールで表示する |
| FR-WORDS-02 | 繁体字・注音・拼音・意味を対象に部分一致で検索できる |
| FR-WORDS-03 | タグで絞り込める |
| FR-WORDS-04 | インポート・エクスポートを実行できる（[9章](#9-インポートエクスポート仕様)） |
| FR-WORDS-05 | 選択した単語を一括削除できる。削除前に件数を示し、取り消せないことを明示して確認する。タグで絞り込んでから「表示中をすべて選択」すれば、タグ単位や全件の削除もこの操作で行える |
| FR-WORDS-06 | （廃止。版 1.5）全データの削除は FR-WORDS-05 で行う |
| FR-WORDS-07 | 「単語パッケージ」から、目的別の単語集（TOCFL など）やサンプル単語を追加できる（[16.5](#165-単語パッケージ)・[11章](#11-サンプル単語仕様)） |
| FR-WORDS-08 | 選択した単語に、タグをまとめて追加できる。また、選択した単語から指定したタグをまとめて外せる。タグが上限（20件）に達している単語には追加せず、その件数を示す |
| FR-WORDS-09 | 単語1語ごとにタグを編集（追加・削除、複数可）できる。入力中は登録済みのタグを候補として示す |
| FR-WORDS-10 | タグの一覧を、各タグの単語数とともに表示する。タグの名前を変更できる。既にあるタグ名に変更した場合は、2つのタグを1つにまとめる |
| FR-WORDS-11 | タグを全単語から外せる（単語は削除しない）。単語を削除する操作ではないことがわかる表示にする |
| FR-WORDS-12 | 選択の操作（表示中をすべて選択、タグの追加・削除、削除）は、一覧をスクロールしても届く位置に置く。タブレット・PC では画面上部に固定する。スマホでは1語以上選んでいるときに画面下部に固定して表示する |

| FR-WORDS-13 | 「重複単語の整理」で、重複している単語（6.1）の組を一覧し、選んだ組をまとめて統合できる。統合する前に、統合後の内容と下記の規則（とくに発音と学習進捗のどちらを残すか）を示し、取り消せないことを明示して確認する |

- 一覧は長くなるため、一覧より下にボタンや操作を置かない。
- 「重複単語の整理」のボタンには、重複している組の数を示す。重複があっても自動では統合せず、統合を促す表示もしない（わざと重複させて使う利用者がいるため）。

重複単語の統合の規則（FR-WORDS-13、およびインポートの「統合する」。FR-IO-03）：

| 項目 | 規則 |
|---|---|
| 残す単語（id） | 先に登録した単語（`createdAt` が古い方）。古い JSON のバックアップとの対応が保たれる。インポートでは既存の単語 |
| 注音・拼音 | 残す単語の値。空なら、もう一方の値を使う |
| 意味 | 同じなら1つ。異なれば ` / ` でつなげて両方残す |
| 例文 | 両方残す。同じ例文は1つにまとめる |
| タグ | 両方のタグをすべて残す |
| 作成日時・更新日時 | 作成日時は古い方。更新日時は統合した日時 |
| 学習進捗 | 学習モードごとに、最後に学習した記録（`Progress.updatedAt` が新しい方）を残し、残す単語の id に付け替える。もう一方の記録は削除する。インポートの「統合する」では既存の単語の記録を優先する |
| 上限を超える場合 | 統合すると意味（500文字）・例文（10件）・タグ（20件）の上限を超える組は統合せず、「手動での整理が必要」として示す |
| 書き込み | 単語と学習進捗の更新を1つのトランザクションで行う（NFR-07） |
| 組の作り方 | 繁体字ごとにまとめる。同じ繁体字で拼音が2種類以上ある場合は拼音ごとに組にし、拼音が空の単語は（どの組に入れるか決められないため）組に含めない |
- 単語を削除すると、その単語の学習進捗も削除する。セッション履歴は残す。
- タグの編集（FR-WORDS-08〜11）では単語の `updatedAt` を更新する。学習進捗は変わらない。
- タグ以外の項目（繁体字・意味など）の編集は v1.0 では扱わない（[16.1](#161-決定事項) の決定 2）。

## 6. データ仕様

### 6.1 単語（Word）
```ts
interface Word {
  id: string;          // UUID（crypto.randomUUID()）
  hanzi: string;       // 繁体字
  zhuyin: string;      // 注音。音節は半角スペース区切り（例: "ㄐㄧㄝˊ ㄩㄣˋ"）
  pinyin: string;      // 拼音。声調記号付き、音節は半角スペース区切り（例: "jié yùn"）
  meaning: string;     // 意味
  examples: Example[]; // 例文（0件以上）
  tags: string[];      // タグ（0件以上、重複なし）
  createdAt: number;   // 作成日時（UNIX ミリ秒）
  updatedAt: number;   // 更新日時（UNIX ミリ秒）
}

interface Example {
  text: string;         // 例文（繁体字）
  translation?: string; // 例文の訳
}
```

| 項目 | 必須 | 制約 |
|---|---|---|
| hanzi | ○ | 1〜50文字。前後の空白は除去する |
| zhuyin | | 0〜200文字 |
| pinyin | | 0〜200文字 |
| meaning | ○ | 1〜500文字。言語は問わない |
| examples | | 0〜10件。各 text は1〜500文字 |
| tags | | 0〜20件。各タグ1〜50文字。前後の空白は除去する。`;` は使えない（CSV のタグ区切りのため） |

- 注音・拼音が空の単語も登録できる。空の項目は学習画面に表示しない。
- **重複の判定**：`hanzi` が一致し、かつ `pinyin` が一致する単語を重複とみなす（同じ字で読みが異なる単語を区別するため）。ただし、どちらかの `pinyin` が空なら `hanzi` だけで判定する（拼音を入力しない利用者が多いため）。比較の前に前後の空白を除去し、拼音は小文字に揃える。判定は `io/duplicates.ts` に集約する。
- 重複した単語を登録したままでも動作に問題はない。単語は id で区別され、学習進捗も単語ごとに別々に記録される（暗記カードでは別々のカードとして出題される）。

### 6.2 学習進捗（Progress）
学習モードごとに、単語ごとの進捗を保存する。形式はモードが決める。
```ts
interface Progress<S = unknown> {
  modeId: string;
  wordId: string;
  due: number | null; // 次回出題日時（SRS を使わないモードは null）
  state: S;           // モード固有の状態
  updatedAt: number;
}
```

### 6.3 セッション履歴（Session）
```ts
interface SessionRecord {
  id?: number;        // 自動採番
  modeId: string;
  startedAt: number;
  finishedAt: number;
  summary: Record<string, number>; // モード固有の集計（例: 評価ごとの件数）
}
```

### 6.4 設定（Setting）
キーと値の組で保存する（`{ key: string; value: unknown }`）。内容は[10章](#10-設定仕様)。

### 6.5 データベーススキーマ（Dexie）
```ts
db.version(1).stores({
  words:    'id, hanzi, pinyin, *tags, updatedAt',
  progress: '[modeId+wordId], modeId, wordId, due',
  sessions: '++id, modeId, startedAt',
  settings: 'key',
});
```
- 単語を削除したときは、その単語の進捗も削除する。
- スキーマを変更するときは `version(n).upgrade()` で既存データを移行する。データを失うスキーマ変更はしない。
- 単語を追加した時点で `navigator.storage.persist()` を要求し、ブラウザによるデータの自動削除を防ぐ（FR-PWA-04）。

## 7. 学習モードのプラグイン仕様

### 7.1 インターフェース
```ts
interface StudyMode<Options = unknown> {
  id: string;                       // 一意な ID（例: 'flashcard'）。進捗の保存キーにもなるため変更しない
  titleKey: string;                 // モード名の i18n キー
  descriptionKey: string;           // 説明文の i18n キー
  icon: React.ComponentType;
  minWords?: number;                // 開始に必要な最少単語数（既定 1）
  requiredFields?: (keyof Word)[];  // 出題対象とする単語に必須の項目
  defaultOptions: Options;          // 準備画面のオプション初期値
  Setup?: React.LazyExoticComponent<React.ComponentType<SetupProps<Options>>>;
  Session: React.LazyExoticComponent<React.ComponentType<SessionProps<Options>>>;
  SettingsPanel?: React.LazyExoticComponent<React.ComponentType<SettingsPanelProps>>; // 設定画面に表示するモード別設定
  Result?: React.LazyExoticComponent<React.ComponentType<ResultProps>>; // 結果画面の集計の表示（省略時は summary をそのまま並べる）
  locales: Record<UiLanguage, Record<string, string>>;
  getBadge?(ctx: ModeContext): Promise<number | null>;
}

interface SetupProps<O> {
  options: O;
  onChange(options: O): void;
}

interface SessionProps<O> {
  words: Word[];             // 準備画面の条件で絞り込んだ単語
  options: O;
  progress: ProgressStore;   // このモード専用の進捗 API（modeId で自動的に区切られる）
  modeSettings: ModeSettingsStore; // このモード専用の設定 API（キー mode.<modeId>.*）
  services: CoreServices;
  onFinish(result: SessionResult): void;
  onAbort(): void;
}

interface SettingsPanelProps {
  settings: ModeSettingsStore;
}

interface ResultProps {
  summary: Record<string, number>; // onFinish で渡した集計
}

interface ProgressStore {        // modeId で自動的に区切られる
  get(wordId: string): Promise<Progress | undefined>;
  getMany(wordIds: string[]): Promise<Map<string, Progress>>;
  list(): Promise<Progress[]>;   // このモードの進捗をすべて返す
  put(wordId: string, due: number | null, state: unknown): Promise<void>;
  dueBefore(time: number): Promise<Progress[]>; // 期限が time 以前のものを古い順に返す
}

interface ModeSettingsStore {    // キーには "mode.<modeId>." が自動で付く
  get<T>(key: string): Promise<T | undefined>;
  set(key: string, value: unknown): Promise<void>;
}

interface CoreServices {
  speak(text: string): void;  // 読み上げ（zh-TW）
  canSpeak: boolean;          // 読み上げに対応しているか
  settings: AppSettings;      // 共通設定（参照のみ）
  tags: TagService;           // 単語のタグの読み書き
}

interface TagService {
  list(): Promise<string[]>;  // 登録済みの全タグ（入力候補用）
  setWordTags(wordId: string, tags: string[]): Promise<string[]>; // 1語のタグを置き換え、保存後のタグを返す
}
```

### 7.2 規約
| ID | 要件 |
|---|---|
| FR-PLUG-01 | モードは `src/modes/<modeId>/` に置き、`src/modes/registry.ts` に登録するだけでホームに表示される。コア（ページ・DB・ルーティング）の変更は不要とする |
| FR-PLUG-02 | `Setup`・`Session`・`SettingsPanel` は `React.lazy` で遅延読み込みする。使わないモードのコードは読み込まない |
| FR-PLUG-03 | モードの文言は i18next の名前空間 `mode.<modeId>` として登録し、モード内で完結させる |
| FR-PLUG-04 | モードは DB に直接アクセスせず、`ProgressStore` と `SessionProps` 経由でのみデータを扱う。単語のタグの変更は `CoreServices.tags` 経由で行う。1語のタグ編集のダイアログは共通部品（`components/WordTagsDialog.tsx`）を使える |

## 8. 暗記カードモード仕様

### 8.1 出題
| ID | 要件 |
|---|---|
| FR-FC-01 | 出題対象は「復習期限が来た単語」と「新規カード」。復習期限の古い順に出し、その後に新規カードを出す |
| FR-FC-02 | 新規カードは1日あたりの上限まで出す（モード設定。初期値 20、範囲 0〜200）。日付は端末のローカル時刻の午前4時で切り替わる |
| FR-FC-03 | 出題対象が0件のときは、次の復習予定日時を表示し、「新規カードを追加で学習する」を選べる |
| FR-FC-04 | 出題の向きを「繁体字→意味」「意味→繁体字」「ランダム」から選べる（準備画面のオプション） |

- 新規カードは登録の古い順に出す。「ランダム」の向きはカードごとに決める。
- 1日の上限（FR-FC-02）は、進捗の状態に保存した「初めて学習した日時」が今日（午前4時以降）である件数で数える。中断や複数回のセッションをまたいでも合算する。
- FR-FC-03 の「新規カードを追加で学習する」では、その日の上限とは別に、上限と同じ枚数（上限が 0 のときは 20 枚）を出す。未学習の単語が残っていない場合はボタンを出さず、次の復習予定日時だけを示す。
- ホームのバッジ（FR-HOME-02）には、復習期限が来ている単語の件数を表示する（新規カードは含めない）。

### 8.2 カード表示
| ID | 要件 |
|---|---|
| FR-FC-10 | 表面には繁体字（または意味）だけを表示する |
| FR-FC-11 | 裏面には繁体字・注音・拼音・意味・例文（訳を含む）・タグを表示する |
| FR-FC-12 | 注音・拼音の表示／非表示をそれぞれモード設定で切り替えられる（初期値：両方表示） |
| FR-FC-13 | 読み上げに対応した環境では、繁体字と例文の読み上げボタンを表示する。非対応の環境ではボタンを表示しない |
| FR-FC-14 | 「裏返したときに自動で読み上げる」をモード設定で選べる（初期値：オフ） |
| FR-FC-15 | 裏面からその単語のタグを編集（追加・削除）できる。単語データ画面の FR-WORDS-09 と同じダイアログを使い、登録済みのタグを候補に示す。例：今の自分が特に覚えたい単語に印を付ける |

- FR-FC-15 で変えたタグは、すぐに裏面の表示に反映する。セッションの出題対象は変えない（対象のタグを外しても、そのセッションでは出題を続ける）。
- タグの編集中は、カードのキーボード操作（評価・中断など）を受け付けない。保存に失敗したときはダイアログ内で通知する（NFR-07）。

### 8.3 評価と SRS
| ID | 要件 |
|---|---|
| FR-FC-20 | 裏面を表示した後、「もう一度」「難しい」「普通」「簡単」「完璧」の5段階で評価する |
| FR-FC-21 | 評価に応じて次回の出題日時を SRS（SM-2 の簡略版）で算出し、保存する。各評価ボタンには次回までの間隔（例：「3日」）を表示する |
| FR-FC-22 | 「もう一度」と評価した単語は、同じセッション内で数枚後に再び出題する |
| FR-FC-23 | SRS の計算は `srs.ts` に分離し、UI から独立した純粋関数とする（将来 FSRS などに差し替えられるようにする） |

SM-2 簡略版の算出規則（`ease` 初期値 2.5、下限 1.3、間隔の単位は日）：

| 評価 | 初回 | 「もう一度」の後 | 2回目以降 | ease |
|---|---|---|---|---|
| もう一度 | 10分後に再出題。連続正解回数を0に戻す | 同左 | 同左 | −0.20 |
| 難しい | 1日 | 1日 | 前回の間隔 × 1.2（最低1日） | −0.15 |
| 普通 | 7日 | 1日 | 前回の間隔 × ease（最低は初回の日数） | 変更なし |
| 簡単 | 60日 | 4日 | 「普通」の間隔 × 1.3（最低は初回の日数） | +0.15 |
| 完璧 | 365日 | 365日 | 「普通」の間隔 × 2（最低は初回の日数） | +0.15 |

- 「初回」は進捗がない単語（初めて学習する単語）。「もう一度の後」は連続正解回数が0の単語（「もう一度」と評価した後、まだ正解していない単語）。「2回目以降」は連続正解回数が1以上の単語。
- 「初回」と「もう一度の後」の日数は、`srs.ts` の間隔表（`IntervalConfig`）にまとめて定める。将来、利用者が日数を変えられるようにする場合（[15章](#15-実装計画マイルストーン)）は、この表の値を設定から渡す。「2回目以降」の倍率は固定とする。
- 「難しい」「普通」「簡単」「完璧」はいずれも連続正解回数を1増やす。
- 間隔は四捨五入して日単位にし、最低1日とする。「普通」「簡単」「完璧」の計算には、その評価で ease を更新する前の値を使う。
- 既存の進捗の形式は変わらないため、移行は不要とする。
- 日単位の間隔の復習期限は、「今日」（午前4時で切り替わる日付）から数えて間隔の日数後の午前4時とする。例：夜 22 時に「普通」（1日）と評価した単語は、翌日の午前4時から出題される。「もう一度」だけは評価した時刻から10分後とする。
- 評価ボタンの間隔は、1時間未満は分、30日未満は日、365日未満は月（30日＝1か月）、それ以上は年で表示する。月と年は小数点以下1桁まで示す（例：「10分」「3日」「1.5か月」「1.2年」）。
- FR-FC-22 の再出題は3枚後とする。残りが3枚未満なら最後に出す。

### 8.4 操作
| ID | 端末 | 操作 |
|---|---|---|
| FR-FC-30 | タッチ | カードをタップして裏返す。裏面で左スワイプ＝「もう一度」、右スワイプ＝「普通」。ボタンでも評価できる |
| FR-FC-31 | キーボード | `Space`：裏返す、`1`〜`5`：評価、`S`：読み上げ、`T`：タグの編集（裏面）、`Esc`：中断 |
| FR-FC-32 | 共通 | 中断したとき、1枚以上評価していれば結果画面を表示し、セッション履歴に保存する。1枚も評価していなければホームへ戻る。確認は求めない |

- スワイプ中はカードが指に合わせて動き、カードの幅の 25% を超えて離すと評価が決まる。
- 「意味→繁体字」の向きの表面では、答えがわかってしまうため読み上げない。
- 評価の保存に失敗したときは画面に通知し、次のカードに進まない（NFR-07）。

### 8.5 結果画面
| ID | 要件 |
|---|---|
| FR-FC-40 | 学習した枚数、評価ごとの件数、所要時間、次回の復習予定（明日の件数）を表示する |

- 「学習した枚数」は単語の数（同じ単語を2回評価しても1枚）、評価ごとの件数は評価した回数で数える。
- 「明日の件数」は、明日の終わり（翌々日の午前4時）までに復習期限が来る単語の件数とする（今日やり残した分を含む）。

## 9. インポート／エクスポート仕様

### 9.1 JSON 形式
単語の全項目と、任意で学習進捗を含む完全な形式。
```json
{
  "format": "tc-vocab",
  "version": 1,
  "exportedAt": "2026-11-09T12:00:00.000Z",
  "words": [
    {
      "hanzi": "捷運",
      "zhuyin": "ㄐㄧㄝˊ ㄩㄣˋ",
      "pinyin": "jié yùn",
      "meaning": "MRT（都市鉄道）",
      "examples": [
        { "text": "我每天坐捷運去公司。", "translation": "毎日MRTで会社に行きます。" }
      ],
      "tags": ["交通"]
    }
  ],
  "progress": []
}
```
- `id`・`createdAt`・`updatedAt` は出力するが、インポート時は省略してよい（省略時は自動で付与する）。
- `progress` はエクスポート時に「学習進捗を含める」を選んだときだけ出力する。

### 9.2 CSV 形式
表計算ソフトで編集するための簡易形式。
- 1行目はヘッダー行とし、列は次のとおり。列の順序は問わない（ヘッダー名で判定する）。

| 列名 | 対応する項目 | 備考 |
|---|---|---|
| `hanzi` | 繁体字 | 必須 |
| `zhuyin` | 注音 | |
| `pinyin` | 拼音 | |
| `meaning` | 意味 | 必須 |
| `example` | 例文（1件目） | |
| `example_translation` | 例文の訳（1件目） | |
| `tags` | タグ | `;` 区切り |

- CSV で扱う例文は1件のみ。2件以上の例文を持つ単語を CSV に出力した場合は1件目だけを出力し、出力前に「例文の一部が失われる単語の件数」を警告する。
- 文字コードは UTF-8。出力時は BOM を付ける（Excel で文字化けしないため）。読み込みは BOM の有無を問わない。BOM 付きの UTF-16 も読み込める（Excel の「Unicode テキスト」）。
- 区切り文字はカンマ、改行や `"` を含む値はダブルクォートで囲む（RFC 4180）。読み込みでは、1行目にカンマが無ければタブ、次にセミコロンを区切り文字とみなす。
- 列名は上の表の英語の名前と完全に一致させる。ただし、前後の空白、大文字・小文字、全角・半角（Unicode の NFKC 正規化で同じになるもの）は区別しない。
- 上の表にない列名の列と、同じ列名の2つ目以降の列は取り込まず、プレビューで列名を示す。
- 日本語・中国語などの列名（例：「繁体字」「意味」「標籤」）は、対応する列として取り込まない。列名の取り違えとわかる場合は、直し方（例：「繁体字 → hanzi」）を示す。必須の列がそろわないときはファイル全体をエラーにし（FR-IO-08）、そろっているときはプレビューで示す。対応の推測に使う別名の表は `io/csv.ts` の `COLUMN_ALIASES` に置く。

### 9.3 インポート手順
| ID | 要件 |
|---|---|
| FR-IO-01 | ファイル選択、またはドラッグ＆ドロップでファイルを受け付ける。形式は拡張子で判定する（`.json` は JSON、`.csv`・`.tsv`・`.txt` は CSV。`.txt` は Excel の「Unicode テキスト」を想定） |
| FR-IO-02 | 取り込む前に検証し、「新規」「重複」「エラー」の件数と内容をプレビュー表示する。エラーは行番号（JSON は配列の番号）と理由を示す |
| FR-IO-03 | 登録済みの単語と重複する単語（6.1）があれば、プレビューに件数を目立たせて示し、扱いを「重複分はインポートしない」（初期値）「重複分もインポートする」「既存の単語と統合する」から選べる。JSON では、バックアップの復元のために「上書きする」も選べる |
| FR-IO-04 | 取り込む全単語に共通のタグを追加できる（初期値：空。例：`imported-2026-11`） |
| FR-IO-05 | エラーのある行は取り込まず、正常な行だけを取り込める |
| FR-IO-06 | 取り込みは1つのトランザクションで行い、途中で失敗した場合は何も取り込まない |
| FR-IO-07 | ファイルサイズの上限は 20MB とする |

- FR-IO-03 の各選択肢には短い説明を添える。「重複分もインポートする」には、あとで「重複単語の整理」（FR-WORDS-13）でまとめられること。「既存の単語と統合する」には、意味・例文・タグは両方とも残ること、発音と学習進捗は既存の単語が優先されること。
- 「上書きする」は誤操作を防ぐため、取り込む前に、上書きする単語の数と、意味・例文・タグ（ファイルに含まれていれば学習進捗も）が置き換わり元に戻せないことを示して確認する。
- 「既存の単語と統合する」で上限を超える単語は、統合せずに別の単語として追加し、その件数を完了の通知で示す。
- 重複分も取り込んだ場合は、完了の通知で件数と「重複単語の整理」でまとめられることを示す。
| FR-IO-08 | 想定外のファイルは取り込まず、理由と直し方を示す（下表）。文字化けした内容を取り込まないことを優先し、文字コードの推測はしない |
| FR-IO-09 | ファイルを選ぶ前の画面に、CSV の作り方の案内を表示する。案内には、列名・内容・例の表、列名を英語で正確に書く必要があることの注意、テンプレートのダウンロード（列名だけの `tc-vocab-template.csv` と、2語入りの `tc-vocab-sample.csv`）を含める |
| FR-IO-10 | 同じ画面に、表計算ソフトから UTF-8 の CSV で保存する手順を示す（Excel の Windows 版・Mac 版、Google スプレッドシート、Numbers）。「CSV（コンマ区切り）」と「CSV UTF-8（コンマ区切り）」の取り違えに注意を促す。文字コードの誤りや Excel のファイルで読めなかったときは、この手順を開いた状態で示す |

FR-IO-08 で扱うファイルと表示：

| ファイル | 判定 | 表示する理由と直し方 |
|---|---|---|
| 拡張子が `.xlsx` `.xls` `.xlsm` `.ods` `.numbers`、または中身が Excel 形式（拡張子を `.csv` に変えたものを含む） | 拡張子と先頭のバイト列 | 表計算ソフトのファイルはそのまま読めない。「CSV UTF-8（コンマ区切り）」で保存し直す |
| 上記以外で拡張子が `.csv` `.json` でない | 拡張子 | `.csv` か `.json` を選ぶ |
| UTF-8 として正しくない（Shift_JIS・Big5 など） | 厳密な UTF-8 の復号 | 文字コードが UTF-8 でない。「CSV UTF-8（コンマ区切り）」で保存し直す |
| 空のファイル、空白だけのファイル | 内容 | ファイルが空である |
| NUL 文字を含む（画像・圧縮ファイルなど） | 内容 | テキストのファイルでない |
| 列名が日本語・中国語などで、必須の列（`hanzi`・`meaning`）がそろわない | 1行目（9.2 の別名の表） | 列名が正しくないことと、直し方（例：「繁体字 → hanzi」）を示す |
| CSV に必須の列（`hanzi`・`meaning`）が無い（上記以外） | 1行目 | 足りない列名と、見つかった列名を示す |
| 列はあるが値が不正な行 | 行ごとの検証（6.1） | プレビューにエラーとして行番号と理由を示し、その行は取り込まない（FR-IO-05） |

### 9.4 エクスポート
| ID | 要件 |
|---|---|
| FR-IO-10 | 形式（JSON / CSV）と対象（全単語 / タグで絞り込み）を選んでファイルをダウンロードできる |
| FR-IO-11 | JSON の場合のみ「学習進捗を含める」を選べる |
| FR-IO-12 | ファイル名は `tc-vocab-YYYYMMDD-HHmm.json`（または `.csv`）とする |

### 9.5 往復の保証
- JSON は、エクスポートしてからインポートすると全項目（進捗を含めた場合は進捗も）が元に戻ること。
- CSV は、例文が1件以下の単語について、全項目が元に戻ること。

## 10. 設定仕様

### 10.1 共通設定
| ID | 項目 | 選択肢 | 初期値 |
|---|---|---|---|
| FR-SET-01 | UI 言語 | 日本語 / 繁體中文 / English | ブラウザの言語設定から判定。`ja*` → 日本語、`zh-TW`・`zh-HK`・`zh-Hant*` → 繁體中文、それ以外 → English |
| FR-SET-02 | 表示サイズ | 小 / 中 / 大 / 特大（ルートの文字サイズを 87.5% / 100% / 125% / 150% にする） | 中 |
| FR-SET-03 | テーマ | ライト / ダーク / システムに従う | システムに従う |
| FR-SET-04 | アクセントカラー | 赤 / 緑 / 青 / 紫 / 橙 / 白黒 | 赤 |

- UI 言語はアプリの画面表示の言語であり、単語の「意味」欄の言語とは関係しない。
- 設定の変更は即座に画面へ反映し、自動で保存する（保存ボタンは設けない）。
- テーマと表示サイズは React の描画より前に保存値を読み込んで適用し、起動時の画面のちらつきを防ぐ。
- ダークモードは `<html data-theme="light|dark">` と CSS カスタムプロパティで切り替える。
- アクセントカラー（FR-SET-04）は `<html data-accent="...">` で切り替える。主なボタン、選択中の表示、進捗バー、ホームのバッジなどに使う。
  - 各色にライト用とダーク用の値を用意し、テーマに合わせて自動で切り替える。「白黒」は、ライトでは黒、ダークでは白になる。
  - アクセントカラーのボタン上の文字は、色ごとに白か黒の読みやすい方を使う。
  - すべての色とテーマの組み合わせで、文字とその背景のコントラスト比が 4.5 以上、ボタンの枠などの部品と背景が 3 以上であること（NFR-03）を単体テストで確かめる。
  - 自由に色を選ぶ方式にはしない（コントラストを保証できないため）。
- エラー、削除のボタン、入力の誤り、暗記カードの「もう一度」などの「危険・注意」の色（`--color-danger`）はアクセントカラーと分け、設定によらず赤とする。肯定の色（`--color-good`。暗記カードの「普通」など）も設定によらず緑とする。

### 10.2 モード別設定
各モードの `SettingsPanel` を設定画面に表示する。暗記カードモードの設定は以下のとおり。

| 項目 | 初期値 |
|---|---|
| 1日の新規カード上限 | 20 |
| 注音を表示 | オン |
| 拼音を表示 | オン |
| 裏返したときに自動で読み上げる | オフ |

| FR-SMP-04 | 単語データ画面の「単語パッケージ」の一覧の先頭に、同梱のパッケージとして示し、いつでも追加できる。通信は不要。既に登録済みの単語は、初期値では重複としてスキップする。重複の扱いは「重複分はインポートしない」「重複分もインポートする」だけを選べる（「タグだけ付ける」「統合する」では、利用者の単語に `サンプル` タグが付き、FR-SMP-05 の一括削除で消えてしまうため） |
| FR-SMP-05 | 不要になったサンプル単語は、`サンプル` タグによる一括削除（FR-WORDS-05）でまとめて削除できる |

- サンプル単語の読み（注音・拼音）は台湾の教育部の標準（《國語辭典》）に従う。
- サンプル単語には、内容に応じた分類タグ（例：`交通`、`食べ物`）も併せて付ける。

## 12. PWA・デプロイ仕様

### 12.1 PWA
| ID | 要件 |
|---|---|
| FR-PWA-01 | アプリ本体（HTML・JS・CSS・アイコン・サンプル単語）をキャッシュし、オフラインで全機能が動作する |
| FR-PWA-02 | ホーム画面にインストールできる。manifest には名前、アイコン（192px・512px・maskable）、`display: "standalone"`、`start_url: "./"` を設定する |
| FR-PWA-03 | 新しいバージョンを検出したら「更新があります」と通知し、利用者の操作で再読み込みする（`registerType: 'prompt'`）。学習セッション中は通知を保留する |
| FR-PWA-04 | データが残りにくい環境に備える（下記）。設定画面に、データの保存の状態（ブラウザによる自動削除から保護されているか）を表示する |

データが残りにくい環境（プライベートブラウズ、終了時にサイトデータを消す設定、一部のアプリ内ブラウザ、しばらく開かないとデータを消す iPhone の Safari など）では、起動するたびに単語が0件になる。
- 「初回起動」はフラグや Cookie では判定せず、単語が0件かどうかで判定する（FR-HOME-05）。単語が消えた環境でも、案内は単語を追加する手段としてそのまま役に立つ。
- 案内はホーム画面に埋め込むカードとし、ポップアップにしない。閉じる操作や「次回から表示しない」は設けない（単語を追加すれば自然に消えるため、保存する状態が要らない）。
- 案内のカードの中に、「プライベートブラウズなどでは、ブラウザを閉じると単語が消えることがあります。ホーム画面に追加すると消えにくくなります」と小さく示す。
- `navigator.storage.persist()` は、単語を追加した時点（守るべきデータができた時点）で要求する。

補足（M4 で決定）：
- 事前キャッシュは HTML・JS・CSS・アイコン・`samples/starter.json` とし、`packs/`（16.5 の単語パッケージ）は含めない。
- アイコンは favicon と同じ意匠（赤地に白の「字」）とし、`public/icons/` に 192px・512px・maskable（512px、余白付き）と、iPhone 用の apple-touch-icon（180px）を置く。manifest の名前は「學中文 tc-vocab」、短い名前は「學中文」。
- 更新の通知（FR-PWA-03）は画面下部のバーとし、「再読み込み」と「あとで」を置く。「あとで」で閉じた通知は、次に起動したときに改めて出す。学習セッション中（モード画面のセッションの段階）は出さず、準備・結果やほかの画面に移ったら出す。開いたままでも気づけるよう、オンラインのときは1時間ごとに更新を確認する（確認先は公開元だけ。NFR-06）。
- 設定画面の「データ」に、保存の状態を「保護されています」「保護されていません」「このブラウザでは確認できません」のいずれかで示す（FR-PWA-04）。保護されていないときは、ホーム画面に追加すると保護されやすいことと、エクスポートでの保存を案内する。保護を要求するボタンは設けない。

### 12.2 デプロイ
- `main` ブランチへの push を契機に、GitHub Actions でビルド・テストを行い、GitHub Pages にデプロイする。
- 公開 URL は `https://<GitHubユーザー名>.github.io/tc-vocab/`。Vite の `base` は `/tc-vocab/` とする。

### 16.3 単語の個別追加・編集の実装方針
インポートを使わずに、アプリの中で単語を1語ずつ追加・編集できるようにする。実装に入る前に、要件 ID を付けて 4.5 に追記する。

| 項目 | 方針 |
|---|---|
| 入口 | 単語データ画面に「単語を追加」ボタンを置く。一覧の各行と暗記カードの裏面から、その単語の編集を開く（暗記カードからは `CoreServices` に編集用の API を足す） |
| 入力画面 | ダイアログ（`components/WordEditDialog.tsx`）。繁体字・意味（必須）、注音、拼音、例文と訳（追加・削除、10件まで）、タグ（`TagField` を使う）。続けて追加できるよう「保存して次へ」を置く |
| 検証 | インポートと同じ `io/validate.ts` の `normalizeWord` を使い、6.1 の制約をそのまま当てる。エラーは項目の下に示す |
| 重複 | 繁体字と拼音が同じ単語があれば保存前に知らせ、「既存の単語を開く」「このまま追加する」を選べる（6.1 の重複の判定と同じ規則） |
| 保存 | `db/repos/words.ts` に `addWord`・`updateWord` を追加する。編集では `updatedAt` だけを更新し、学習進捗は変えない |
| 読みの入力補助 | 拼音と注音は音節の対応表（約400音節）で相互に変換できるため、片方を入れるともう片方を候補として示す。繁体字から読みを自動で付けるには辞書データ（教育部《國語辭典》など）が必要で、容量とライセンスの確認が要るため、別途検討する |
| 音声 | 単語ごとの音声ファイルは持たない。読み上げは端末の音声合成（Web Speech API、`zh-TW` の音声）が繁体字の文字列からその場で行うため、アプリ内で追加した単語も追加の作業なしで読み上げられる。ただし、多音字の読み分けは音声合成に任せることになり、拼音の通りに読ませることはできない。自分の声を録音して単語に付ける機能は、容量・エクスポート形式への影響が大きいため、必要になったら別途検討する |


### 16.4 注音・拼音の自動付与
声調記号つきの拼音や注音は、利用者が自分で入力するのが難しい。インポート後や単語の追加時に、アプリが読みを付けられるようにする。2段階に分けて進める。

**段階1：入力の補助（辞書データ不要。16.3 と同時に行う）**

| 項目 | 方針 |
|---|---|
| 数字の声調 | `jie2 yun4`・`jie2yun4` のような数字つき拼音を受け付け、声調記号つき（`jié yùn`）に直す。インポートと単語の追加の両方で行う |
| 拼音と注音の変換 | 音節の対応表（約400音節、数 KB）で相互に変換する。片方だけが入力されていれば、もう片方を自動で埋める |

**段階2：繁体字からの自動付与（将来）**

| 項目 | 方針 |
|---|---|
| 操作 | インポートのプレビューと単語の一覧で「読みが空の単語に読みを付ける」を選べる。付けた読みは確定前に一覧で確認・修正できる |
| 仕組み | 辞書データ（単語とその読み）を、使うときだけ読み込む。長い単語から順に一致させ（最長一致）、辞書にない部分は1字ずつ読みを引く |
| 多音字 | 「行」（háng / xíng）、「長」（cháng / zhǎng）のように読みが複数ある字は、単語として辞書にあれば正しく付く。1字だけで判定する場合や辞書にない語は、もっともよく使われる読みを付け、タグ `要確認:読み` を付ける（タグで絞り込んで確認できる） |
| 辞書データ | 教育部《重編國語辭典修訂本》から、見出し語と注音だけを抜き出して使う（決定。規約上の問題はないものとして進める）。ビルド時のスクリプトで `public/dict/zhuyin.json` を作り、拼音は注音から音節の対応表で変換する（辞書の拼音は使わない） |
| 出典の表示 | 設定画面に、注音の出典（教育部《重編國語辭典修訂本》）とライセンス（創用CC 姓名標示-禁止改作 3.0 臺灣）を示す |

段階2の課題：

| 課題 | 内容 |
|---|---|
| データの入手 | 教育部の公眾授權網から辞典のデータファイルをダウンロードする。ダウンロードは実装を始めるときに利用者の承認を得て行う |
| 容量 | 単語数万語分の辞書は数 MB になる。初回表示には含めず（NFR-02）、読みを付ける操作をしたときに読み込む。オフラインで使うには、読み込んだデータを端末に保存する |
| 正確さ | 自動で付けた読みは誤ることがある（多音字、固有名詞、新語）。必ず利用者が確認できるようにし、確認前の読みは区別して示す |
| 読み上げとの関係 | 音声合成（[16.3](#163-単語の個別追加編集の実装方針)）は拼音を参照しないため、付けた読みが正しくても読み上げの多音字の誤りは直らない |

### 16.5 単語パッケージ
アプリの操作だけで、目的別の単語のまとまり（例：ネットスラング、コンピュータ用語、旅行会話）を追加できるようにする。

| 項目 | 方針 |
|---|---|
| 配布場所 | アプリと同じ GitHub Pages の `public/packs/` に置く。一覧 `index.json`（ID・名前・説明・単語数・版・ライセンス）と、パッケージごとの JSON（9.1 の形式）。同じサイト内のファイルを読むだけなので、外部への通信をしない方針（NFR-06）に反しない。サンプル単語（11章）と同じ仕組み |
| 画面 | 単語データ画面のツールバーに「単語パッケージ」を置く（「サンプル単語を追加」はこれに置き換え、サンプル単語は一覧の先頭に示す。FR-SMP-04）。一覧から選ぶと、単語数・容量・数語の見本を示し、インポートと同じプレビュー（新規・重複の件数）を経て追加する。ホームの案内からは、単語データ画面を開いて一覧を表示する（`#/words?open=packs`） |
| 最初の案内 | 単語が0件のときのホーム画面の案内（FR-HOME-05）を「単語を追加して始めましょう」とし、次の3つを並べる。(1) 単語パッケージを選ぶ（TOCFL・HSK などの目的別の単語集を選んですぐに学習を始められることを示す） (2) サンプル単語を追加（約50語、通信不要） (3) 自分のファイルをインポート |
| 通信と容量の表示 | 単語パッケージの一覧と各パッケージに、ダウンロードにインターネット接続が必要なことと、ダウンロードの容量（例：「約 1.2 MB」。index.json に記録する）を示す。オフラインのときは「インターネットに接続すると選べます」と示し、サンプル単語とインポートは使えるようにする |
| タグ | 追加した単語には、パッケージで決めたタグ（例：`HSK` と `HSK5`、`TOCFL` と `TOCFL:進階`）を自動で付ける。不要になったら、そのタグで絞り込んで全選択し、削除できる（FR-WORDS-05） |
| 重複 | 既にある単語（6.1）は、初期値では「タグだけ付ける」とする。既存の単語の意味・例文・読み・学習進捗は変えず、パッケージのタグだけを加える。1つの単語が複数の単語集に入っていれば、タグが増えていく（例：`HSK4` と `TOCFL:進階`）。タグが上限（20件）を超える単語は変更せず、件数を示す。ほかに、FR-IO-03 と同じ「統合する」「重複分もインポートする」「インポートしない」も選べる。「タグだけ付ける」はパッケージでだけ選べる（ファイルのインポートでは選べない）。サンプル単語の扱いは FR-SMP-04 による |
| 更新 | 追加したパッケージの ID と版を `settings` テーブルのキー `packs.installed` に記録し、一覧に「追加済み」と示す。パッケージの版が上がったら一覧に「更新あり」と示す。更新では、新しく加わった単語を追加し、既にある単語にはタグだけを付ける。パッケージ側で直した内容（意味の修正など）は、利用者が編集した内容を上書きしないよう自動では反映しない。変更点を示して反映できるようにするかは、作るときに決める |
| オフライン | 一覧とパッケージは使うときに読み込む。初回表示や PWA の事前キャッシュには含めない（M4） |
| 一覧の形式 | 下記の `index.json`。各パッケージの単語は 9.1 の JSON 形式とし、単語ごとに級などのタグ（例：`TOCFL`・`TOCFL:入門`）を入れておく |
| 作成と審査 | パッケージはリポジトリに JSON を追加して作る。読み（16.4）・意味・例文の確認と、出典のライセンスの確認を経てから公開する |
| 対象外 | 任意の URL から外部のパッケージを読み込む機能は作らない（NFR-06 と、内容の安全性を確かめられないため）。個人どうしの共有は、JSON ファイルのエクスポート・インポートで行う |

一覧 `public/packs/index.json` の形式：
```json
{
  "format": "tc-vocab-packs",
  "version": 1,
  "packs": [
    {
      "id": "tocfl-novice",
      "file": "tocfl-novice.json",
      "version": 1,
      "name": { "ja": "TOCFL 入門・基礎", "zh-TW": "TOCFL 入門・基礎", "en": "TOCFL Novice" },
      "description": { "ja": "華語文能力測驗の入門・基礎の単語。意味は AI による下書き", "zh-TW": "…", "en": "…" },
      "wordCount": 1000,
      "size": 245760,
      "tags": ["TOCFL", "TOCFL:入門", "TOCFL:基礎"],
      "meaningLanguage": "ja",
      "license": "…",
      "source": "…"
    }
  ]
}
```
- `id` は `^[a-z0-9][a-z0-9-]*$`。追加済みの記録に使うので、公開後は変えない。`file` は `packs/` からの相対パス。`version` は内容を変えるたびに 1 増やす整数。
- `name`・`description` は UI 言語ごとの文字列。無い言語は `ja`、次に最初の項目で代用する。`size` はパッケージの JSON のバイト数（容量の表示に使う）。`tags` は一覧に示すタグ（実際に付くタグは単語ごとの `tags`）。
- `format` や `version` が想定と違う一覧、形式の誤ったパッケージは読み込まず、その旨を示す。サンプル単語はこの一覧に含めず、アプリが一覧の先頭に加える。
- 任意の項目 `levelGuide` に、試験の級の対応表（例：TOCFL の各級に相当する TBCL の級）を書ける。`title`・`note` と、列 `columns`（`tocfl`・`cefr`・`listening`・`reading`）の見出しは UI 言語ごとの文字列。`rows[]` の各行は `{ tocfl, cefr, listening, reading, inPack, tag? }`（`tocfl` は UI 言語ごとの文字列、`inPack` はこのパッケージに収めている級か、`tag` はその級の単語に付けるタグ）。`source` は出典（`name` と `url`）。形式の誤った対応表は表示しないだけで、パッケージは使える。
- このほかの項目（`updatedAt`・`meaningNote`・`tagCounts`・`sources` など）は、アプリは読まずに無視する。
- 一覧では、各パッケージに `tags` を示し、対象の試験と級がわかるようにする（例：`TOCFL`・`TOCFL:入門`）。選んだあとのプレビューでは、`levelGuide` があれば対応表を示し（収めている級の行を目立たせる）、`source` と `license` を「出典とライセンス」として示す。

主な課題は技術よりも内容にある。単語・意味・例文の作成と校閲の手間、辞書やウェブから集める場合の著作権、意味を何語で書くか（UI 言語ごとに用意するか）を、最初のパッケージを作る前に決める。

サンプル単語（11章）はアプリに同梱し、TOCFL・HSK などの単語集は事前に入れずに単語パッケージとして配る（決定）。使わない単語で一覧や出題がふさがらないこと、目的（台湾の TOCFL か中国大陸の HSK か）で選べること、パッケージごとに更新できることによる。

TOCFL・HSK の単語集の作り方（公式の語彙表は公開されており、単語集として配ってよいものとして進める。決定）：

| 手順 | 担当 | 方針 |
|---|---|---|
| 語彙表の入手 | Claude | 公式サイトから語彙表を入手する。元のファイルは \`scripts/packs/sources/\` に置き、出典と入手日を記録する。ダウンロードは利用者の承認を得て行う |
| 繁体字への変換（HSK） | スクリプト | HSK の語彙表は簡体字のため、台湾の字形・語彙への変換表（OpenCC の簡体字→台湾正體など、再配布できるもの）で繁体字にする。変換が一意に決まらない語は一覧にして確認する |
| 注音・拼音 | スクリプト | 教育部《重編國語辭典修訂本》の注音（16.4）で付け、拼音は注音から変換する。辞書にない語は \`要確認:読み\` タグを付ける |
| 日本語の意味 | Claude | 数百語ずつ下書きする。パッケージの説明に「意味は AI による下書き」と示す |
| 確認 | 利用者 | 抜き取りで確認してから公開する |
| タグと版 | スクリプト | 級ごとのタグ（例：\`TOCFL\`・\`TOCFL:入門\`、\`HSK\`・\`HSK5\`）を付け、\`public/packs/\` に版つきで出力する |

- 量が多いため（TOCFL は約8千語、新しい HSK は1〜9級で1万語を超える）、まず TOCFL の入門・基礎（約1千語）で試し、品質と手順を確かめてから広げる。
- 変換と出力のスクリプトは \`scripts/packs/\` に置き、語彙表の更新時に作り直せるようにする。

### 16.6 簡体字の併記
繁体字を学ぶ人が簡体字も見られるよう、また簡体字に慣れた人が使えるよう、字体の表示を選べるようにする（将来）。

| 項目 | 方針 |
|---|---|
| 設定 | 共通設定（10.1）に「字体の表示」を追加する。「繁体字のみ」（初期値）、「繁体字＋簡体字」、「簡体字＋繁体字」、「簡体字のみ」 |
| 併記の見た目 | 主に表示する字体のすぐ横に、もう一方を少し小さく（約 0.6 倍）、薄い色（\`--color-muted\`）で表示する。両方が同じ字（例：「人」「水」）のときは併記しない |
| 対象 | 単語データ画面の一覧、暗記カードの表面・裏面、例文。学習モードには、コアが字体を変換する関数を \`CoreServices\` で渡す |
| データ | 正本は繁体字（\`hanzi\`）のままとし、検索・重複の判定・並べ替えは繁体字で行う。簡体字は表示のたびに変換表（OpenCC の繁体字→簡体字など）で作る。変換表は、この設定を選んだときだけ読み込む（NFR-02） |
| 個別の指定 | 変換で正しくならない語のために、将来、単語に簡体字の項目（任意）を設け、CSV の列 \`simplified\` で指定できるようにすることを検討する |
| 検索 | 併記を選んでいるときは、簡体字でも検索できるようにする |
| 言語の指定 | 簡体字の部分には \`lang="zh-CN"\`（またはzh-Hans）を付け、フォントは \`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif\` の順で指定する（NFR-04・05） |
| 読み・読み上げ | 「簡体字のみ」でも、読み（注音・拼音）と読み上げは台湾の規範のままとする |
