## 1. 目的と範囲

### 1.1 目的
繁体中文（台湾華語）の単語を、PC・タブレット・スマートフォンで学習できるブラウザアプリを提供する。

### 1.2 基本方針
- サーバーを持たない。データはすべて利用者の端末内（IndexedDB）に保存する。
- PWA としてインストールでき、オフラインで動作する。
- 学習モードはプラグイン式とし、コアを変更せずに追加できるようにする。

### 1.3 v1.0 の範囲
| 区分 | 内容 |
|---|---|
| 対象 | 初期画面（モード選択）、暗記カードモード、単語データ画面（一覧・インポート・エクスポート）、設定画面、サンプル単語、PWA、GitHub Pages での公開 |
| 対象外 | クイズモード、漢字なぞりモード、画面上での単語の個別追加・編集、統計画面、端末間同期、アカウント機能 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 単語 | 学習の最小単位。繁体字・注音・拼音・意味・例文・タグを持つ（[6.1](#61-単語-word)） |
| タグ | 単語に付けるラベル。単語リスト（単語帳）の役割も兼ねる |
| 学習モード | 単語を学習する方法（暗記カード、クイズなど）。プラグインとして実装する |
| セッション | 学習モードの開始から結果表示までの1回分の学習 |
| SRS | 間隔反復（Spaced Repetition System）。記憶の定着度に応じて次の出題日を決める仕組み |
| 復習期限 | SRS が算出した、その単語を次に出題すべき日時 |
| 新規カード | そのモードでまだ一度も学習していない単語 |

               └─→ SC-04 単語データ

### 4.3 SC-01 ホーム
| ID | 要件 |
|---|---|
| FR-HOME-01 | 登録済みの学習モードをカード形式で一覧表示する。各カードにアイコン・名称・説明を表示する |
| FR-HOME-02 | モードがバッジを提供する場合（例：暗記カードの復習待ち件数）、カードに表示する |
| FR-HOME-03 | 単語数がモードの必要語数（`minWords`）に満たない場合、そのカードを無効表示にし、理由を示す |
| FR-HOME-04 | 設定画面へのリンクを常に表示する |
| FR-HOME-05 | 単語が0件のとき、単語データ画面への案内（インポート／サンプル単語の追加）を表示する |

### 4.4 SC-02 モード画面
| ID | 要件 |
|---|---|
| FR-MODE-01 | 準備画面で、対象とするタグ（複数選択可、未選択は全単語）とモード固有のオプションを選べる |
| FR-MODE-02 | 準備画面で選んだ条件は次回の初期値として保存する |
| FR-MODE-03 | セッション中に中断できる。中断時点までの学習結果は保存する |
| FR-MODE-04 | セッション終了後に結果画面を表示し、ホームへ戻る・もう一度学習する操作を提供する |

### 4.5 SC-04 単語データ
| ID | 要件 |
|---|---|
| FR-WORDS-01 | 単語を一覧表示する（繁体字・注音・拼音・意味・タグ）。件数が多い場合は仮想スクロールで表示する |
| FR-WORDS-02 | 繁体字・注音・拼音・意味を対象に部分一致で検索できる |
| FR-WORDS-03 | タグで絞り込める |
| FR-WORDS-04 | インポート・エクスポートを実行できる（[9章](#9-インポートエクスポート仕様)） |
| FR-WORDS-05 | 選択した単語を一括削除できる。削除前に件数を示し、取り消せないことを明示して確認する。タグで絞り込んでから「表示中をすべて選択」すれば、タグ単位や全件の削除もこの操作で行える |
| FR-WORDS-06 | （廃止。版 1.5）全データの削除は FR-WORDS-05 で行う |
| FR-WORDS-07 | サンプル単語を追加できる（[11章](#11-サンプル単語仕様)） |
| FR-WORDS-08 | 選択した単語に、タグをまとめて追加できる。また、選択した単語から指定したタグをまとめて外せる。タグが上限（20件）に達している単語には追加せず、その件数を示す |
| FR-WORDS-09 | 単語1語ごとにタグを編集（追加・削除、複数可）できる。入力中は登録済みのタグを候補として示す |
| FR-WORDS-10 | タグの一覧を、各タグの単語数とともに表示する。タグの名前を変更できる。既にあるタグ名に変更した場合は、2つのタグを1つにまとめる |
| FR-WORDS-11 | タグを全単語から外せる（単語は削除しない）。単語を削除する操作ではないことがわかる表示にする |
| FR-WORDS-12 | 選択の操作（表示中をすべて選択、タグの追加・削除、削除）は、一覧をスクロールしても届く位置に置く。タブレット・PC では画面上部に固定する。スマホでは1語以上選んでいるときに画面下部に固定して表示する |

- 一覧は長くなるため、一覧より下にボタンや操作を置かない。
- 単語を削除すると、その単語の学習進捗も削除する。セッション履歴は残す。
- タグの編集（FR-WORDS-08〜11）では単語の `updatedAt` を更新する。学習進捗は変わらない。
- タグ以外の項目（繁体字・意味など）の編集は v1.0 では扱わない（[16.1](#161-決定事項) の決定 2）。

## 5. レスポンシブ仕様

| 区分 | 画面幅 | レイアウト | 操作 |
|---|---|---|---|
| スマホ | 〜599px | 1カラム。モードは縦並び。主要ボタンは画面下部（親指が届く位置）に配置 | タッチ前提。タップ領域は 44×44px 以上。スワイプ操作に対応。hover に依存する表示をしない |

- ノッチ等に対応するため `env(safe-area-inset-*)` を考慮し、全画面の高さには `100dvh` を使う。

## 6. データ仕様

### 6.1 単語（Word）
```ts
interface Word {
  id: string;          // UUID（crypto.randomUUID()）
  hanzi: string;       // 繁体字
  zhuyin: string;      // 注音。音節は半角スペース区切り（例: "ㄐㄧㄝˊ ㄩㄣˋ"）
  pinyin: string;      // 拼音。声調記号付き、音節は半角スペース区切り（例: "jié yùn"）
  meaning: string;     // 意味
  examples: Example[]; // 例文（0件以上）
  tags: string[];      // タグ（0件以上、重複なし）
  createdAt: number;   // 作成日時（UNIX ミリ秒）
  updatedAt: number;   // 更新日時（UNIX ミリ秒）
}

interface Example {
  text: string;         // 例文（繁体字）
  translation?: string; // 例文の訳
}
```

| 項目 | 必須 | 制約 |
|---|---|---|
| hanzi | ○ | 1〜50文字。前後の空白は除去する |
| zhuyin | | 0〜200文字 |
| pinyin | | 0〜200文字 |
| meaning | ○ | 1〜500文字。言語は問わない |
| examples | | 0〜10件。各 text は1〜500文字 |
| tags | | 0〜20件。各タグ1〜50文字。前後の空白は除去する。`;` は使えない（CSV のタグ区切りのため） |

- 注音・拼音が空の単語も登録できる。空の項目は学習画面に表示しない。
- **重複の判定**：`hanzi` と `pinyin` が両方一致する単語を重複とみなす（同じ字で読みが異なる単語を区別するため）。比較の前に前後の空白を除去し、拼音は小文字に揃える。

### 6.2 学習進捗（Progress）
学習モードごとに、単語ごとの進捗を保存する。形式はモードが決める。
```ts
interface Progress<S = unknown> {
  modeId: string;
  wordId: string;
  due: number | null; // 次回出題日時（SRS を使わないモードは null）
  state: S;           // モード固有の状態
  updatedAt: number;
}
```

### 6.3 セッション履歴（Session）
```ts
interface SessionRecord {
  id?: number;        // 自動採番
  modeId: string;
  startedAt: number;
  finishedAt: number;
  summary: Record<string, number>; // モード固有の集計（例: 評価ごとの件数）
}
```

### 6.4 設定（Setting）
キーと値の組で保存する（`{ key: string; value: unknown }`）。内容は[10章](#10-設定仕様)。

### 6.5 データベーススキーマ（Dexie）
```ts
db.version(1).stores({
  words:    'id, hanzi, pinyin, *tags, updatedAt',
  progress: '[modeId+wordId], modeId, wordId, due',
  sessions: '++id, modeId, startedAt',
  settings: 'key',
});
```
- 単語を削除したときは、その単語の進捗も削除する。
- スキーマを変更するときは `version(n).upgrade()` で既存データを移行する。データを失うスキーマ変更はしない。
- 初回起動時に `navigator.storage.persist()` を要求し、ブラウザによるデータの自動削除を防ぐ。

## 7. 学習モードのプラグイン仕様

### 7.1 インターフェース
```ts
interface StudyMode<Options = unknown> {
  id: string;                       // 一意な ID（例: 'flashcard'）。進捗の保存キーにもなるため変更しない
  titleKey: string;                 // モード名の i18n キー
  descriptionKey: string;           // 説明文の i18n キー
  icon: React.ComponentType;
  minWords?: number;                // 開始に必要な最少単語数（既定 1）
  requiredFields?: (keyof Word)[];  // 出題対象とする単語に必須の項目
  defaultOptions: Options;          // 準備画面のオプション初期値
  Setup?: React.LazyExoticComponent<React.ComponentType<SetupProps<Options>>>;
  Session: React.LazyExoticComponent<React.ComponentType<SessionProps<Options>>>;
  SettingsPanel?: React.LazyExoticComponent<React.ComponentType<SettingsPanelProps>>; // 設定画面に表示するモード別設定
  Result?: React.LazyExoticComponent<React.ComponentType<ResultProps>>; // 結果画面の集計の表示（省略時は summary をそのまま並べる）
  locales: Record<UiLanguage, Record<string, string>>;
  getBadge?(ctx: ModeContext): Promise<number | null>;
}

interface SetupProps<O> {
  options: O;
  onChange(options: O): void;
}

interface SessionProps<O> {
  words: Word[];             // 準備画面の条件で絞り込んだ単語
  options: O;
  progress: ProgressStore;   // このモード専用の進捗 API（modeId で自動的に区切られる）
  modeSettings: ModeSettingsStore; // このモード専用の設定 API（キー mode.<modeId>.*）
  services: CoreServices;
  onFinish(result: SessionResult): void;
  onAbort(): void;
}

interface SettingsPanelProps {
  settings: ModeSettingsStore;
}

interface ResultProps {
  summary: Record<string, number>; // onFinish で渡した集計
}

interface ProgressStore {        // modeId で自動的に区切られる
  get(wordId: string): Promise<Progress | undefined>;
  getMany(wordIds: string[]): Promise<Map<string, Progress>>;
  list(): Promise<Progress[]>;   // このモードの進捗をすべて返す
  put(wordId: string, due: number | null, state: unknown): Promise<void>;
  dueBefore(time: number): Promise<Progress[]>; // 期限が time 以前のものを古い順に返す
}

interface ModeSettingsStore {    // キーには "mode.<modeId>." が自動で付く
  get<T>(key: string): Promise<T | undefined>;
  set(key: string, value: unknown): Promise<void>;
}

interface CoreServices {
  speak(text: string): void;  // 読み上げ（zh-TW）
  canSpeak: boolean;          // 読み上げに対応しているか
  settings: AppSettings;      // 共通設定（参照のみ）
  tags: TagService;           // 単語のタグの読み書き
}

interface TagService {
  list(): Promise<string[]>;  // 登録済みの全タグ（入力候補用）
  setWordTags(wordId: string, tags: string[]): Promise<string[]>; // 1語のタグを置き換え、保存後のタグを返す
}
```

### 7.2 規約
| ID | 要件 |
|---|---|
| FR-PLUG-01 | モードは `src/modes/<modeId>/` に置き、`src/modes/registry.ts` に登録するだけでホームに表示される。コア（ページ・DB・ルーティング）の変更は不要とする |
| FR-PLUG-02 | `Setup`・`Session`・`SettingsPanel` は `React.lazy` で遅延読み込みする。使わないモードのコードは読み込まない |
| FR-PLUG-03 | モードの文言は i18next の名前空間 `mode.<modeId>` として登録し、モード内で完結させる |
| FR-PLUG-04 | モードは DB に直接アクセスせず、`ProgressStore` と `SessionProps` 経由でのみデータを扱う。単語のタグの変更は `CoreServices.tags` 経由で行う。1語のタグ編集のダイアログは共通部品（`components/WordTagsDialog.tsx`）を使える |
| FR-PLUG-05 | モード固有の設定は `settings` テーブルのキー `mode.<modeId>.*` に保存する。読み書きは `ModeSettingsStore`（`SessionProps.modeSettings`、`SettingsPanelProps.settings`）経由で行う |
| FR-PLUG-06 | モードは結果画面の集計の表示（`Result`）を提供できる。「もう一度」「ホームへ戻る」の操作とセッション履歴の保存はコア（`ModePage`）が行う |

## 8. 暗記カードモード仕様

### 8.1 出題
| ID | 要件 |
|---|---|
| FR-FC-01 | 出題対象は「復習期限が来た単語」と「新規カード」。復習期限の古い順に出し、その後に新規カードを出す |
| FR-FC-02 | 新規カードは1日あたりの上限まで出す（モード設定。初期値 20、範囲 0〜200）。日付は端末のローカル時刻の午前4時で切り替わる |
| FR-FC-03 | 出題対象が0件のときは、次の復習予定日時を表示し、「新規カードを追加で学習する」を選べる |
| FR-FC-04 | 出題の向きを「繁体字→意味」「意味→繁体字」「ランダム」から選べる（準備画面のオプション） |

- 新規カードは登録の古い順に出す。「ランダム」の向きはカードごとに決める。
- 1日の上限（FR-FC-02）は、進捗の状態に保存した「初めて学習した日時」が今日（午前4時以降）である件数で数える。中断や複数回のセッションをまたいでも合算する。
- FR-FC-03 の「新規カードを追加で学習する」では、その日の上限とは別に、上限と同じ枚数（上限が 0 のときは 20 枚）を出す。未学習の単語が残っていない場合はボタンを出さず、次の復習予定日時だけを示す。
- ホームのバッジ（FR-HOME-02）には、復習期限が来ている単語の件数を表示する（新規カードは含めない）。

### 8.2 カード表示
| ID | 要件 |
|---|---|
| FR-FC-10 | 表面には繁体字（または意味）だけを表示する |
| FR-FC-11 | 裏面には繁体字・注音・拼音・意味・例文（訳を含む）・タグを表示する |
| FR-FC-12 | 注音・拼音の表示／非表示をそれぞれモード設定で切り替えられる（初期値：両方表示） |
| FR-FC-13 | 読み上げに対応した環境では、繁体字と例文の読み上げボタンを表示する。非対応の環境ではボタンを表示しない |
| FR-FC-14 | 「裏返したときに自動で読み上げる」をモード設定で選べる（初期値：オフ） |
| FR-FC-15 | 裏面からその単語のタグを編集（追加・削除）できる。単語データ画面の FR-WORDS-09 と同じダイアログを使い、登録済みのタグを候補に示す。例：今の自分が特に覚えたい単語に印を付ける |

- FR-FC-15 で変えたタグは、すぐに裏面の表示に反映する。セッションの出題対象は変えない（対象のタグを外しても、そのセッションでは出題を続ける）。
- タグの編集中は、カードのキーボード操作（評価・中断など）を受け付けない。保存に失敗したときはダイアログ内で通知する（NFR-07）。

### 8.3 評価と SRS
| ID | 要件 |
|---|---|
| FR-FC-20 | 裏面を表示した後、「もう一度」「難しい」「普通」「簡単」「完璧」の5段階で評価する |
| FR-FC-21 | 評価に応じて次回の出題日時を SRS（SM-2 の簡略版）で算出し、保存する。各評価ボタンには次回までの間隔（例：「3日」）を表示する |
| FR-FC-22 | 「もう一度」と評価した単語は、同じセッション内で数枚後に再び出題する |
| FR-FC-23 | SRS の計算は `srs.ts` に分離し、UI から独立した純粋関数とする（将来 FSRS などに差し替えられるようにする） |

SM-2 簡略版の算出規則（`ease` 初期値 2.5、下限 1.3、間隔の単位は日）：

| 評価 | 初回 | 「もう一度」の後 | 2回目以降 | ease |
|---|---|---|---|---|
| もう一度 | 10分後に再出題。連続正解回数を0に戻す | 同左 | 同左 | −0.20 |
| 難しい | 1日 | 1日 | 前回の間隔 × 1.2（最低1日） | −0.15 |
| 普通 | 7日 | 1日 | 前回の間隔 × ease（最低は初回の日数） | 変更なし |
| 簡単 | 60日 | 4日 | 「普通」の間隔 × 1.3（最低は初回の日数） | +0.15 |
| 完璧 | 365日 | 365日 | 「普通」の間隔 × 2（最低は初回の日数） | +0.15 |

- 「初回」は進捗がない単語（初めて学習する単語）。「もう一度の後」は連続正解回数が0の単語（「もう一度」と評価した後、まだ正解していない単語）。「2回目以降」は連続正解回数が1以上の単語。
- 「初回」と「もう一度の後」の日数は、`srs.ts` の間隔表（`IntervalConfig`）にまとめて定める。将来、利用者が日数を変えられるようにする場合（[15章](#15-実装計画マイルストーン)）は、この表の値を設定から渡す。「2回目以降」の倍率は固定とする。
- 「難しい」「普通」「簡単」「完璧」はいずれも連続正解回数を1増やす。
- 間隔は四捨五入して日単位にし、最低1日とする。「普通」「簡単」「完璧」の計算には、その評価で ease を更新する前の値を使う。
- 既存の進捗の形式は変わらないため、移行は不要とする。
- 日単位の間隔の復習期限は、「今日」（午前4時で切り替わる日付）から数えて間隔の日数後の午前4時とする。例：夜 22 時に「普通」（1日）と評価した単語は、翌日の午前4時から出題される。「もう一度」だけは評価した時刻から10分後とする。
- 評価ボタンの間隔は、1時間未満は分、30日未満は日、365日未満は月（30日＝1か月）、それ以上は年で表示する。月と年は小数点以下1桁まで示す（例：「10分」「3日」「1.5か月」「1.2年」）。
- FR-FC-22 の再出題は3枚後とする。残りが3枚未満なら最後に出す。

### 8.4 操作
| ID | 端末 | 操作 |
|---|---|---|
| FR-FC-30 | タッチ | カードをタップして裏返す。裏面で左スワイプ＝「もう一度」、右スワイプ＝「普通」。ボタンでも評価できる |
| FR-FC-31 | キーボード | `Space`：裏返す、`1`〜`5`：評価、`S`：読み上げ、`T`：タグの編集（裏面）、`Esc`：中断 |
| FR-FC-32 | 共通 | 中断したとき、1枚以上評価していれば結果画面を表示し、セッション履歴に保存する。1枚も評価していなければホームへ戻る。確認は求めない |

- スワイプ中はカードが指に合わせて動き、カードの幅の 25% を超えて離すと評価が決まる。
- 「意味→繁体字」の向きの表面では、答えがわかってしまうため読み上げない。
- 評価の保存に失敗したときは画面に通知し、次のカードに進まない（NFR-07）。

### 8.5 結果画面
| ID | 要件 |
|---|---|
| FR-FC-40 | 学習した枚数、評価ごとの件数、所要時間、次回の復習予定（明日の件数）を表示する |

- 「学習した枚数」は単語の数（同じ単語を2回評価しても1枚）、評価ごとの件数は評価した回数で数える。
- 「明日の件数」は、明日の終わり（翌々日の午前4時）までに復習期限が来る単語の件数とする（今日やり残した分を含む）。

## 9. インポート／エクスポート仕様

### 9.1 JSON 形式
単語の全項目と、任意で学習進捗を含む完全な形式。
```json
{
  "format": "tc-vocab",
  "version": 1,
  "exportedAt": "2026-11-09T12:00:00.000Z",
  "words": [
    {
      "hanzi": "捷運",
      "zhuyin": "ㄐㄧㄝˊ ㄩㄣˋ",
      "pinyin": "jié yùn",
      "meaning": "MRT（都市鉄道）",
      "examples": [
        { "text": "我每天坐捷運去公司。", "translation": "毎日MRTで会社に行きます。" }
      ],
      "tags": ["交通"]
    }
  ],
  "progress": []
}
```
- `id`・`createdAt`・`updatedAt` は出力するが、インポート時は省略してよい（省略時は自動で付与する）。
- `progress` はエクスポート時に「学習進捗を含める」を選んだときだけ出力する。

### 9.2 CSV 形式
表計算ソフトで編集するための簡易形式。
- 1行目はヘッダー行とし、列は次のとおり。列の順序は問わない（ヘッダー名で判定する）。

| 列名 | 対応する項目 | 備考 |
|---|---|---|
| `hanzi` | 繁体字 | 必須 |
| `zhuyin` | 注音 | |
| `pinyin` | 拼音 | |
| `meaning` | 意味 | 必須 |
| `example` | 例文（1件目） | |
| `example_translation` | 例文の訳（1件目） | |
| `tags` | タグ | `;` 区切り |

- CSV で扱う例文は1件のみ。2件以上の例文を持つ単語を CSV に出力した場合は1件目だけを出力し、出力前に「例文の一部が失われる単語の件数」を警告する。
- 文字コードは UTF-8。出力時は BOM を付ける（Excel で文字化けしないため）。読み込みは BOM の有無を問わない。BOM 付きの UTF-16 も読み込める（Excel の「Unicode テキスト」）。
- 区切り文字はカンマ、改行や `"` を含む値はダブルクォートで囲む（RFC 4180）。読み込みでは、1行目にカンマが無ければタブ、次にセミコロンを区切り文字とみなす。
- 上の表にない列名の列と、同じ列名の2つ目以降の列は取り込まず、プレビューで列名を示す。列名の前後の空白と大文字・小文字は区別しない。

### 9.3 インポート手順
| ID | 要件 |
|---|---|
| FR-IO-01 | ファイル選択、またはドラッグ＆ドロップでファイルを受け付ける。形式は拡張子（`.json` / `.csv`）で判定する |
| FR-IO-02 | 取り込む前に検証し、「新規」「重複」「エラー」の件数と内容をプレビュー表示する。エラーは行番号（JSON は配列の番号）と理由を示す |
| FR-IO-03 | 重複した単語の扱いを「スキップ」「上書き」「両方残す」から選べる（初期値：スキップ） |
| FR-IO-04 | 取り込む全単語に共通のタグを追加できる（初期値：空。例：`imported-2026-11`） |
| FR-IO-05 | エラーのある行は取り込まず、正常な行だけを取り込める |
| FR-IO-06 | 取り込みは1つのトランザクションで行い、途中で失敗した場合は何も取り込まない |
| FR-IO-07 | ファイルサイズの上限は 20MB とする |
| FR-IO-08 | 想定外のファイルは取り込まず、理由と直し方を示す（下表）。文字化けした内容を取り込まないことを優先し、文字コードの推測はしない |
| FR-IO-09 | ファイルを選ぶ前の画面に、CSV の作り方の案内（列名・内容・例の表と注意点）を表示する。見本の CSV（`tc-vocab-template.csv`。2語入り）をダウンロードできる |

FR-IO-08 で扱うファイルと表示：

| ファイル | 判定 | 表示する理由と直し方 |
|---|---|---|
| 拡張子が `.xlsx` `.xls` `.xlsm` `.ods` `.numbers`、または中身が Excel 形式（拡張子を `.csv` に変えたものを含む） | 拡張子と先頭のバイト列 | 表計算ソフトのファイルはそのまま読めない。「CSV UTF-8（コンマ区切り）」で保存し直す |
| 上記以外で拡張子が `.csv` `.json` でない | 拡張子 | `.csv` か `.json` を選ぶ |
| UTF-8 として正しくない（Shift_JIS・Big5 など） | 厳密な UTF-8 の復号 | 文字コードが UTF-8 でない。「CSV UTF-8（コンマ区切り）」で保存し直す |
| 空のファイル、空白だけのファイル | 内容 | ファイルが空である |
| NUL 文字を含む（画像・圧縮ファイルなど） | 内容 | テキストのファイルでない |
| CSV に必須の列（`hanzi`・`meaning`）が無い | 1行目 | 足りない列名と、見つかった列名を示す |
| 列はあるが値が不正な行 | 行ごとの検証（6.1） | プレビューにエラーとして行番号と理由を示し、その行は取り込まない（FR-IO-05） |

### 9.4 エクスポート
| ID | 要件 |
|---|---|
| FR-IO-10 | 形式（JSON / CSV）と対象（全単語 / タグで絞り込み）を選んでファイルをダウンロードできる |
| FR-IO-11 | JSON の場合のみ「学習進捗を含める」を選べる |
| FR-IO-12 | ファイル名は `tc-vocab-YYYYMMDD-HHmm.json`（または `.csv`）とする |

### 9.5 往復の保証
- JSON は、エクスポートしてからインポートすると全項目（進捗を含めた場合は進捗も）が元に戻ること。
- CSV は、例文が1件以下の単語について、全項目が元に戻ること。

### 16.3 単語の個別追加・編集の実装方針
インポートを使わずに、アプリの中で単語を1語ずつ追加・編集できるようにする。実装に入る前に、要件 ID を付けて 4.5 に追記する。

| 項目 | 方針 |
|---|---|
| 入口 | 単語データ画面に「単語を追加」ボタンを置く。一覧の各行と暗記カードの裏面から、その単語の編集を開く（暗記カードからは `CoreServices` に編集用の API を足す） |
| 入力画面 | ダイアログ（`components/WordEditDialog.tsx`）。繁体字・意味（必須）、注音、拼音、例文と訳（追加・削除、10件まで）、タグ（`TagField` を使う）。続けて追加できるよう「保存して次へ」を置く |
| 検証 | インポートと同じ `io/validate.ts` の `normalizeWord` を使い、6.1 の制約をそのまま当てる。エラーは項目の下に示す |
| 重複 | 繁体字と拼音が同じ単語があれば保存前に知らせ、「既存の単語を開く」「このまま追加する」を選べる（6.1 の重複の判定と同じ規則） |
| 保存 | `db/repos/words.ts` に `addWord`・`updateWord` を追加する。編集では `updatedAt` だけを更新し、学習進捗は変えない |
| 読みの入力補助 | 拼音と注音は音節の対応表（約400音節）で相互に変換できるため、片方を入れるともう片方を候補として示す。繁体字から読みを自動で付けるには辞書データ（教育部《國語辭典》など）が必要で、容量とライセンスの確認が要るため、別途検討する |
| 音声 | 単語ごとの音声ファイルは持たない。読み上げは端末の音声合成（Web Speech API、`zh-TW` の音声）が繁体字の文字列からその場で行うため、アプリ内で追加した単語も追加の作業なしで読み上げられる。ただし、多音字の読み分けは音声合成に任せることになり、拼音の通りに読ませることはできない。自分の声を録音して単語に付ける機能は、容量・エクスポート形式への影響が大きいため、必要になったら別途検討する |
