## 1. 目的と範囲

### 1.1 目的
繁体中文（台湾華語）の単語を、PC・タブレット・スマートフォンで学習できるブラウザアプリを提供する。

### 1.2 基本方針
- サーバーを持たない。データはすべて利用者の端末内（IndexedDB）に保存する。
- PWA としてインストールでき、オフラインで動作する。
- 学習モードはプラグイン式とし、コアを変更せずに追加できるようにする。

### 1.3 v1.0 の範囲
| 区分 | 内容 |
|---|---|
| 対象 | 初期画面（モード選択）、暗記カードモード、単語データ画面（一覧・インポート・エクスポート・タグの編集・重複の整理・単語の個別追加と編集）、設定画面、サンプル単語、配布中の単語集、PWA（ホーム画面への追加の手助けを含む）、GitHub Pages での公開 |
| 対象外 | クイズモード、漢字なぞりモード、統計画面、端末間同期、アカウント機能 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 単語 | 学習の最小単位。繁体字・注音・拼音・意味・例文・タグを持つ（[6.1](#61-単語-word)） |
| タグ | 単語に付けるラベル。単語リスト（単語帳）の役割も兼ねる |
| 学習モード | 単語を学習する方法（暗記カード、クイズなど）。プラグインとして実装する |
| セッション | 学習モードの開始から結果表示までの1回分の学習 |
| SRS | 間隔反復（Spaced Repetition System）。記憶の定着度に応じて次の出題日を決める仕組み |
| 復習期限 | SRS が算出した、その単語を次に出題すべき日時 |
| 新規カード | そのモードでまだ一度も学習していない単語 |

| FR-WORDS-08 | 選択した単語に、タグをまとめて追加できる。また、選択した単語から指定したタグをまとめて外せる。タグが上限（20件）に達している単語には追加せず、その件数を示す |
| FR-WORDS-09 | 単語1語ごとにタグを編集（追加・削除、複数可）できる。入力中は登録済みのタグを候補として示す |

| FR-WORDS-11 | タグを全単語から外せる（単語は削除しない）。単語を削除する操作ではないことがわかる表示にする |

| FR-WORDS-14 | タグ `要確認:読み`（読みを確定できなかった単語に付く。タグ名は UI 言語によらず固定）の意味と対処を示す。このタグを持つ単語があるときは、タグでの絞り込みの下とタグの一覧に、単語パッケージ・インポートのプレビューでは件数とともに、「読みを確定できなかった単語です。辞書で確かめ、正しければタグを外してください。読みが違っていれば、単語の編集（FR-WORDS-16）で直してからタグを外します」という趣旨を示す（版 1.16 で、ファイルに書き出して直す方法の案内から差し替え） |
| FR-WORDS-15 | 「単語を追加」で、単語を1語ずつ追加できる。入力画面（`components/WordEditDialog.tsx`）の項目は、繁体字・意味（必須）、注音、拼音、例文と訳（追加・削除、10件まで）、タグ（入力中は登録済みのタグを候補に示す）。検証はインポートと同じ規則（6.1）で行い、エラーは項目の下に示す。追加では「保存」のほかに、続けて入力できる「保存して次へ」を置く。追加した時点で `storage.persist()` を要求する（FR-PWA-04） |
| FR-WORDS-16 | 一覧の各行に「単語を編集」ボタン（FR-WORDS-09 のタグの編集ボタンとは別）を置き、FR-WORDS-15 と同じ入力画面でその単語のすべての項目を編集できる。保存すると `updatedAt` だけを更新し、id・作成日時・学習進捗は変えない。入力を変えたまま閉じようとしたときは、破棄してよいか確かめる |
| FR-WORDS-17 | 追加するとき、および編集で繁体字か拼音を変えたとき、保存の前に重複（6.1 の判定）を調べる。重複する単語があれば、その単語（繁体字・読み・意味）を示し、「既存の単語を開く」「このまま保存する」を選べる。「既存の単語を開く」で開いた画面の「← 戻る」では、入力中の内容に戻る（FR-NAV-01 と同じく1画面ずつ戻る） |
| FR-WORDS-18 | 読みの入力を助ける（[16.4](#164-注音拼音の自動付与) の段階1）。拼音の数字の声調（`jie2 yun4`・`jie2yun4`）は、入力欄を離れたときに声調記号つき（`jié yùn`）に直す。拼音と注音の片方だけが入っているときは、入力欄を離れたときに、もう片方を音節の対応表で変換して自動で埋める。両方が入っていて食い違うときは、変換した読みを「読みの候補」として示し、押すと入れ替える。変換できない音節を含むときは何もしない |
| FR-WORDS-19 | タグの入力欄（`components/TagField.tsx`。単語の追加・編集、1語のタグ編集、選んだ単語へのタグの追加、タグ名の変更）の下に、タグの付け方の例を常に示す（日本語：「例：交通、食べ物、動詞、復習 など、分類や目的に合わせて自由に付けられます」）。入力欄の補足として読み上げられるようにする（`aria-describedby`）。入力欄の中の薄い文字（「例：復習」）は1つのタグの例のままとし、区切って複数入れられると誤解されないようにする |

- 一覧は長くなるため、一覧より下にボタンや操作を置かない。
- 「重複単語の整理」のボタンには、重複している組の数を示す。重複があっても自動では統合せず、統合を促す表示もしない（わざと重複させて使う利用者がいるため）。

重複単語の統合の規則（FR-WORDS-13、およびインポートの「統合する」。FR-IO-03）：

| 項目 | 規則 |
|---|---|
| 残す単語（id） | 先に登録した単語（`createdAt` が古い方）。古い JSON のバックアップとの対応が保たれる。インポートでは既存の単語 |
| 注音・拼音 | 残す単語の値。空なら、もう一方の値を使う |
| 意味 | 同じなら1つ。異なれば ` / ` でつなげて両方残す |
| 例文 | 両方残す。同じ例文は1つにまとめる |
| タグ | 両方のタグをすべて残す |
| 作成日時・更新日時 | 作成日時は古い方。更新日時は統合した日時 |
| 学習進捗 | 学習モードごとに、最後に学習した記録（`Progress.updatedAt` が新しい方）を残し、残す単語の id に付け替える。もう一方の記録は削除する。インポートの「統合する」では既存の単語の記録を優先する |
| 上限を超える場合 | 統合すると意味（500文字）・例文（10件）・タグ（20件）の上限を超える組は統合せず、「手動での整理が必要」として示す |
| 書き込み | 単語と学習進捗の更新を1つのトランザクションで行う（NFR-07） |
| 組の作り方 | 繁体字ごとにまとめる。同じ繁体字で拼音が2種類以上ある場合は拼音ごとに組にし、拼音が空の単語は（どの組に入れるか決められないため）組に含めない |
- 単語を削除すると、その単語の学習進捗も削除する。セッション履歴は残す。
- タグの編集（FR-WORDS-08〜11）では単語の `updatedAt` を更新する。学習進捗は変わらない。
- 画面の日本語の文言では、カタカナの多い語を避ける（例：「単語パッケージ」は「配布中の単語集」（単語データ画面のボタンは「単語集を読み込む」）、「ファイルをインポート」は「ファイルを読み込んで単語を追加」、設定の「UI 言語」は「言語」、「テーマ」は「背景の色」（白 / 黒 / 機器の設定に従う）、「表示サイズ」は「文字の大きさ」、「アクセントカラー」は「ボタンなどの色」、「エクスポート」は「ファイルに書き出す」、「重複分はインポートしない／する」は「重複分は追加しない／も追加する」）。今後の文言でも、不自然なカタカナの多用を避ける。仕様書とコードでは、引き続き「単語パッケージ」（pack）の語を使う。
- タグ以外の項目（繁体字・意味など）の編集は M4.6 で追加した（FR-WORDS-15〜18、[16.3](#163-単語の個別追加編集の実装方針)、[16.1](#161-決定事項) の決定 2）。入力画面はダイアログで、ブラウザの履歴には加えない。閉じると開いた元の画面（単語データ画面・暗記カード）に戻る。

### 4.6 共通の操作
| ID | 要件 |
|---|---|
| FR-NAV-01 | ホーム以外の画面（設定、単語データ、モード画面の準備と結果）では、画面の題名の左に「← 戻る」（矢印と文字。押せる範囲は 44px 以上）を置く。押すと1つ前の画面に戻る。アプリ内に戻る先が無いとき（その画面を直接開いたときなど）は、1つ上の階層の画面（今はどれもホーム）に移る。画面遷移が深くなっても、ホームへ一気に戻るのではなく1画面ずつ戻る。学習セッション中は置かない（中断の操作で戻る）。ヘッダーのアプリ名はホームへのリンクとする |

## 5. レスポンシブ仕様

| 区分 | 画面幅 | レイアウト | 操作 |
|---|---|---|---|
| スマホ | 〜599px | 1カラム。モードは縦並び。主要ボタンは画面下部（親指が届く位置）に配置 | タッチ前提。タップ領域は 44×44px 以上。スワイプ操作に対応。hover に依存する表示をしない |

- ノッチ等に対応するため `env(safe-area-inset-*)` を考慮し、全画面の高さには `100dvh` を使う。

## 6. データ仕様

### 6.1 単語（Word）
```ts
interface Word {
  id: string;          // UUID（crypto.randomUUID()）
  hanzi: string;       // 繁体字
  zhuyin: string;      // 注音。音節は半角スペース区切り（例: "ㄐㄧㄝˊ ㄩㄣˋ"）
  pinyin: string;      // 拼音。声調記号付き、音節は半角スペース区切り（例: "jié yùn"）
  meaning: string;     // 意味
  examples: Example[]; // 例文（0件以上）
  tags: string[];      // タグ（0件以上、重複なし）
  createdAt: number;   // 作成日時（UNIX ミリ秒）
  updatedAt: number;   // 更新日時（UNIX ミリ秒）
}

interface Example {
  text: string;         // 例文（繁体字）
  translation?: string; // 例文の訳
}
```

| 項目 | 必須 | 制約 |
|---|---|---|
| hanzi | ○ | 1〜50文字。前後の空白は除去する |
| zhuyin | | 0〜200文字 |
| pinyin | | 0〜200文字 |
| meaning | ○ | 1〜500文字。言語は問わない |
| examples | | 0〜10件。各 text は1〜500文字 |
| tags | | 0〜20件。各タグ1〜50文字。前後の空白は除去する。`;` は使えない（CSV のタグ区切りのため） |

- 注音・拼音が空の単語も登録できる。空の項目は学習画面に表示しない。
- **重複の判定**：`hanzi` が一致し、かつ `pinyin` が一致する単語を重複とみなす（同じ字で読みが異なる単語を区別するため）。ただし、どちらかの `pinyin` が空なら `hanzi` だけで判定する（拼音を入力しない利用者が多いため）。比較の前に前後の空白を除去し、拼音は小文字に揃える。判定は `io/duplicates.ts` に集約する。
- 重複した単語を登録したままでも動作に問題はない。単語は id で区別され、学習進捗も単語ごとに別々に記録される（暗記カードでは別々のカードとして出題される）。

### 6.2 学習進捗（Progress）
学習モードごとに、単語ごとの進捗を保存する。形式はモードが決める。
```ts
interface Progress<S = unknown> {
  modeId: string;
  wordId: string;
  due: number | null; // 次回出題日時（SRS を使わないモードは null）
  state: S;           // モード固有の状態
  updatedAt: number;
}
```

### 6.3 セッション履歴（Session）
```ts
interface SessionRecord {
  id?: number;        // 自動採番
  modeId: string;
  startedAt: number;
  finishedAt: number;
  summary: Record<string, number>; // モード固有の集計（例: 評価ごとの件数）
}
```

### 6.4 設定（Setting）
キーと値の組で保存する（`{ key: string; value: unknown }`）。内容は[10章](#10-設定仕様)。

### 6.5 データベーススキーマ（Dexie）
```ts
db.version(1).stores({
  words:    'id, hanzi, pinyin, *tags, updatedAt',
  progress: '[modeId+wordId], modeId, wordId, due',
  sessions: '++id, modeId, startedAt',
  settings: 'key',
});
```
- 単語を削除したときは、その単語の進捗も削除する。
- スキーマを変更するときは `version(n).upgrade()` で既存データを移行する。データを失うスキーマ変更はしない。
- 単語を追加した時点で `navigator.storage.persist()` を要求し、ブラウザによるデータの自動削除を防ぐ（FR-PWA-04）。

## 8. 暗記カードモード仕様

### 8.1 出題
| ID | 要件 |
|---|---|
| FR-FC-01 | 出題対象は「復習期限が来た単語」と「新規カード」。復習期限の古い順に出し、その後に新規カードを出す |
| FR-FC-02 | 新規カードは1日あたりの上限まで出す（モード設定。初期値 20、範囲 0〜200）。日付は端末のローカル時刻の午前4時で切り替わる |
| FR-FC-03 | 出題対象が0件のときは、次の復習予定日時を表示し、「新規カードを追加で学習する」を選べる |
| FR-FC-04 | 出題の向きを「繁体字→意味」「意味→繁体字」「ランダム」から選べる（準備画面のオプション） |

- 新規カードは登録の古い順に出す。「ランダム」の向きはカードごとに決める。
- 1日の上限（FR-FC-02）は、進捗の状態に保存した「初めて学習した日時」が今日（午前4時以降）である件数で数える。中断や複数回のセッションをまたいでも合算する。
- FR-FC-03 の「新規カードを追加で学習する」では、その日の上限とは別に、上限と同じ枚数（上限が 0 のときは 20 枚）を出す。未学習の単語が残っていない場合はボタンを出さず、次の復習予定日時だけを示す。
- ホームのバッジ（FR-HOME-02）には、復習期限が来ている単語の件数を表示する（新規カードは含めない）。

### 8.2 カード表示
| ID | 要件 |
|---|---|
| FR-FC-10 | 表面には繁体字（または意味）だけを表示する |
| FR-FC-11 | 裏面には繁体字・注音・拼音・意味・例文（訳を含む）・タグを表示する |
| FR-FC-12 | 注音・拼音の表示／非表示をそれぞれモード設定で切り替えられる（初期値：両方表示） |
| FR-FC-13 | 読み上げに対応した環境では、繁体字と例文の読み上げボタンを表示する。非対応の環境ではボタンを表示しない |
| FR-FC-14 | 「裏返したときに自動で読み上げる」をモード設定で選べる（初期値：オフ） |
| FR-FC-15 | 裏面からその単語のタグを編集（追加・削除）できる。単語データ画面の FR-WORDS-09 と同じダイアログを使い、登録済みのタグを候補に示す。例：今の自分が特に覚えたい単語に印を付ける |
| FR-FC-16 | 裏面から、その単語の編集（FR-WORDS-16 と同じ入力画面）を開ける。「タグを編集」（FR-FC-15）とは別のボタンにする。保存した内容はすぐに裏面の表示に反映し、学習進捗とセッションの出題対象は変えない。重複の確認（FR-WORDS-17）では「このまま保存する」だけを選べる（学習中は別の単語を開かない） |

- FR-FC-15 で変えたタグは、すぐに裏面の表示に反映する。セッションの出題対象は変えない（対象のタグを外しても、そのセッションでは出題を続ける）。
- タグや単語の編集中は、カードのキーボード操作（評価・中断など）を受け付けない。保存に失敗したときはダイアログ内で通知する（NFR-07）。

### 8.3 評価と SRS
| ID | 要件 |
|---|---|
| FR-FC-20 | 裏面を表示した後、「もう一度」「難しい」「普通」「簡単」「完璧」の5段階で評価する |
| FR-FC-21 | 評価に応じて次回の出題日時を SRS（SM-2 の簡略版）で算出し、保存する。各評価ボタンには次回までの間隔（例：「3日」）を表示する |
| FR-FC-22 | 「もう一度」と評価した単語は、同じセッション内で数枚後に再び出題する |
| FR-FC-23 | SRS の計算は `srs.ts` に分離し、UI から独立した純粋関数とする（将来 FSRS などに差し替えられるようにする） |

SM-2 簡略版の算出規則（`ease` 初期値 2.5、下限 1.3、間隔の単位は日）：

| 評価 | 初回 | 「もう一度」の後 | 2回目以降 | ease |
|---|---|---|---|---|
| もう一度 | 10分後に再出題。連続正解回数を0に戻す | 同左 | 同左 | −0.20 |
| 難しい | 1日 | 1日 | 前回の間隔 × 1.2（最低1日） | −0.15 |
| 普通 | 7日 | 1日 | 前回の間隔 × ease（最低は初回の日数） | 変更なし |
| 簡単 | 60日 | 4日 | 「普通」の間隔 × 1.3（最低は初回の日数） | +0.15 |
| 完璧 | 365日 | 365日 | 「普通」の間隔 × 2（最低は初回の日数） | +0.15 |

- 「初回」は進捗がない単語（初めて学習する単語）。「もう一度の後」は連続正解回数が0の単語（「もう一度」と評価した後、まだ正解していない単語）。「2回目以降」は連続正解回数が1以上の単語。
- 「初回」と「もう一度の後」の日数は、`srs.ts` の間隔表（`IntervalConfig`）にまとめて定める。将来、利用者が日数を変えられるようにする場合（[15章](#15-実装計画マイルストーン)）は、この表の値を設定から渡す。「2回目以降」の倍率は固定とする。
- 「難しい」「普通」「簡単」「完璧」はいずれも連続正解回数を1増やす。
- 間隔は四捨五入して日単位にし、最低1日とする。「普通」「簡単」「完璧」の計算には、その評価で ease を更新する前の値を使う。
- 既存の進捗の形式は変わらないため、移行は不要とする。
- 日単位の間隔の復習期限は、「今日」（午前4時で切り替わる日付）から数えて間隔の日数後の午前4時とする。例：夜 22 時に「普通」（1日）と評価した単語は、翌日の午前4時から出題される。「もう一度」だけは評価した時刻から10分後とする。
- 評価ボタンの間隔は、1時間未満は分、30日未満は日、365日未満は月（30日＝1か月）、それ以上は年で表示する。月と年は小数点以下1桁まで示す（例：「10分」「3日」「1.5か月」「1.2年」）。
- FR-FC-22 の再出題は3枚後とする。残りが3枚未満なら最後に出す。

### 8.4 操作
| ID | 端末 | 操作 |
|---|---|---|
| FR-FC-30 | タッチ | カードをタップして裏返す。裏面で左スワイプ＝「もう一度」、右スワイプ＝「普通」。ボタンでも評価できる |
| FR-FC-31 | キーボード | `Space`：裏返す、`1`〜`5`：評価、`S`：読み上げ、`T`：タグの編集（裏面）、`E`：単語の編集（裏面）、`Esc`：中断 |
| FR-FC-32 | 共通 | 中断したとき、1枚以上評価していれば結果画面を表示し、セッション履歴に保存する。1枚も評価していなければホームへ戻る。確認は求めない |

- スワイプ中はカードが指に合わせて動き、カードの幅の 25% を超えて離すと評価が決まる。
- 「意味→繁体字」の向きの表面では、答えがわかってしまうため読み上げない。
- 評価の保存に失敗したときは画面に通知し、次のカードに進まない（NFR-07）。

### 8.5 結果画面
| ID | 要件 |
|---|---|

- 「学習した枚数」は単語の数（同じ単語を2回評価しても1枚）、評価ごとの件数は評価した回数で数える。

## 9. インポート／エクスポート仕様

### 9.1 JSON 形式
単語の全項目と、任意で学習進捗を含む完全な形式。
```json
{
  "format": "tc-vocab",
  "version": 1,
  "exportedAt": "2026-11-09T12:00:00.000Z",
  "words": [
    {
      "hanzi": "捷運",
      "zhuyin": "ㄐㄧㄝˊ ㄩㄣˋ",
      "pinyin": "jié yùn",
      "meaning": "MRT（都市鉄道）",
      "examples": [
        { "text": "我每天坐捷運去公司。", "translation": "毎日MRTで会社に行きます。" }
      ],
      "tags": ["交通"]
    }
  ],
  "progress": []
}
```
- `id`・`createdAt`・`updatedAt` は出力するが、インポート時は省略してよい（省略時は自動で付与する）。
- `progress` はエクスポート時に「学習進捗を含める」を選んだときだけ出力する。
- アプリ全体のバックアップ（[10.4](#104-データの保護バックアップ復元初期化)）は、この形式に `backup`・`appVersion`・`sessions`・`settings` を加えたものとする（版 1.32）。単語の読み込み（9.3）でバックアップのファイルを選んだときは、これまでどおり単語と進捗だけを扱い、ほかの項目は無視する。

### 9.2 CSV 形式
表計算ソフトで編集するための簡易形式。
- 1行目はヘッダー行とし、列は次のとおり。列の順序は問わない（ヘッダー名で判定する）。

| 列名 | 対応する項目 | 備考 |
|---|---|---|
| `hanzi` | 繁体字 | 必須 |
| `zhuyin` | 注音 | |
| `pinyin` | 拼音 | |
| `meaning` | 意味 | 必須 |
| `example` | 例文（1件目） | |
| `example_translation` | 例文の訳（1件目） | |
| `tags` | タグ | `;` 区切り |

- CSV で扱う例文は1件のみ。2件以上の例文を持つ単語を CSV に出力した場合は1件目だけを出力し、出力前に「例文の一部が失われる単語の件数」を警告する。
- 文字コードは UTF-8。出力時は BOM を付ける（Excel で文字化けしないため）。読み込みは BOM の有無を問わない。BOM 付きの UTF-16 も読み込める（Excel の「Unicode テキスト」）。
- 区切り文字はカンマ、改行や `"` を含む値はダブルクォートで囲む（RFC 4180）。読み込みでは、1行目にカンマが無ければタブ、次にセミコロンを区切り文字とみなす。
- 列名は上の表の英語の名前と完全に一致させる。ただし、前後の空白、大文字・小文字、全角・半角（Unicode の NFKC 正規化で同じになるもの）は区別しない。
- 上の表にない列名の列と、同じ列名の2つ目以降の列は取り込まず、プレビューで列名を示す。
- 日本語・中国語などの列名（例：「繁体字」「意味」「標籤」）は、対応する列として取り込まない。列名の取り違えとわかる場合は、直し方（例：「繁体字 → hanzi」）を示す。必須の列がそろわないときはファイル全体をエラーにし（FR-IO-08）、そろっているときはプレビューで示す。対応の推測に使う別名の表は `io/csv.ts` の `COLUMN_ALIASES` に置く。

### 9.3 インポート手順
| ID | 要件 |
|---|---|
| FR-IO-01 | ファイル選択、またはドラッグ＆ドロップでファイルを受け付ける。形式は拡張子で判定する（`.json` は JSON、`.csv`・`.tsv`・`.txt` は CSV。`.txt` は Excel の「Unicode テキスト」を想定） |
| FR-IO-02 | 取り込む前に検証し、「新規」「重複」「エラー」の件数と内容をプレビュー表示する。エラーは行番号（JSON は配列の番号）と理由を示す |
| FR-IO-03 | 登録済みの単語と重複する単語（6.1）があれば、プレビューに件数を目立たせて示し、扱いを「重複分は追加しない」（初期値）「重複分も追加する」「既存の単語と統合する」から選べる。JSON では、バックアップの復元のために「上書きする」も選べる |
| FR-IO-04 | 取り込む全単語に共通のタグを追加できる（初期値：空。例：`imported-2026-11`） |
| FR-IO-05 | エラーのある行は取り込まず、正常な行だけを取り込める |
| FR-IO-06 | 取り込みは1つのトランザクションで行い、途中で失敗した場合は何も取り込まない |
| FR-IO-07 | ファイルサイズの上限は 20MB とする |

- FR-IO-03 の各選択肢には短い説明を添える。「重複分もインポートする」には、あとで「重複単語の整理」（FR-WORDS-13）でまとめられること。「既存の単語と統合する」には、意味・例文・タグは両方とも残ること、発音と学習進捗は既存の単語が優先されること。
- 「上書きする」は誤操作を防ぐため、取り込む前に、上書きする単語の数と、意味・例文・タグ（ファイルに含まれていれば学習進捗も）が置き換わり元に戻せないことを示して確認する。
- 「既存の単語と統合する」で上限を超える単語は、統合せずに別の単語として追加し、その件数を完了の通知で示す。
- 重複分も取り込んだ場合は、完了の通知で件数と「重複単語の整理」でまとめられることを示す。
| FR-IO-08 | 想定外のファイルは取り込まず、理由と直し方を示す（下表）。文字化けした内容を取り込まないことを優先し、文字コードの推測はしない |
| FR-IO-09 | ファイルを選ぶ前の画面に、CSV の作り方の案内を表示する。案内には、列名・内容・例の表、列名を英語で正確に書く必要があることの注意、テンプレートのダウンロード（列名だけの `tc-vocab-template.csv` と、2語入りの `tc-vocab-sample.csv`）を含める。画面の上部に「自分で用意した単語を、CSV または JSON ファイルから追加できます。Excel などで CSV ファイルを作る方法は、下の説明をご覧ください」という趣旨の案内を置く。表の `tags` の説明には、1つの単語に複数のタグを `;` で区切って付けられることを明記する。案内の下に「既にある単語と重複したとき」の説明（重複の判定（6.1）と、プレビューで件数を示し扱いを選べること（FR-IO-03））を置く |
| FR-IO-10 | 同じ画面に、表計算ソフトから UTF-8 の CSV で保存する手順を示す（Excel の Windows 版・Mac 版、Google スプレッドシート、Numbers）。「CSV（コンマ区切り）」と「CSV UTF-8（コンマ区切り）」の取り違えに注意を促す。文字コードの誤りや Excel のファイルで読めなかったときは、この手順を開いた状態で示す |

FR-IO-08 で扱うファイルと表示：

| ファイル | 判定 | 表示する理由と直し方 |
|---|---|---|
| 拡張子が `.xlsx` `.xls` `.xlsm` `.ods` `.numbers`、または中身が Excel 形式（拡張子を `.csv` に変えたものを含む） | 拡張子と先頭のバイト列 | 表計算ソフトのファイルはそのまま読めない。「CSV UTF-8（コンマ区切り）」で保存し直す |
| 上記以外で拡張子が `.csv` `.json` でない | 拡張子 | `.csv` か `.json` を選ぶ |
| UTF-8 として正しくない（Shift_JIS・Big5 など） | 厳密な UTF-8 の復号 | 文字コードが UTF-8 でない。「CSV UTF-8（コンマ区切り）」で保存し直す |
| 空のファイル、空白だけのファイル | 内容 | ファイルが空である |
| NUL 文字を含む（画像・圧縮ファイルなど） | 内容 | テキストのファイルでない |
| 列名が日本語・中国語などで、必須の列（`hanzi`・`meaning`）がそろわない | 1行目（9.2 の別名の表） | 列名が正しくないことと、直し方（例：「繁体字 → hanzi」）を示す |
| CSV に必須の列（`hanzi`・`meaning`）が無い（上記以外） | 1行目 | 足りない列名と、見つかった列名を示す |
| 列はあるが値が不正な行 | 行ごとの検証（6.1） | プレビューにエラーとして行番号と理由を示し、その行は取り込まない（FR-IO-05） |

- CSV は、例文が1件以下の単語について、全項目が元に戻ること。

- **版の表示（FR-SET-06）**：
  - 表示する版は `package.json` の `version` とし、ビルドのときに埋め込む（Vite の `define`）。フィードバックのフォームに書き込む版（下記）と同じ値を使う。

- **リンクの動作**：押すと新しいタブ（PWA ではブラウザ）でフォームを開く（`target="_blank"`、`rel="noopener noreferrer"`）。アプリの画面は離れない。
- **外部であることの表示**：リンクのそばに「外部のサイト（Google フォーム）が開きます。書いた内容はそのサイトに送られます。単語や学習の記録は送られません」と示す。リンクには外部のページであることを示すアイコンを付け、読み上げ用の名前にも「新しいタブで開きます」を含める（NFR-04）。
- **オフライン**：オフラインのときはリンクを押せない状態にし、「インターネットに接続すると開けます」と示す。オンラインに戻ったら押せるようにする。
- **URL に付ける情報**：フォームの欄にあらかじめ書き込むため、アプリの版（`package.json` の `version`）と画面の言語（FR-SET-01）だけを URL のパラメーターに付ける。単語、学習の記録、設定のほかの値、端末やブラウザの情報、個人を特定できる情報は付けない。
- **フォームの作り**：フォームは開発者が Google フォームで作り、URL と、あらかじめ書き込む欄の ID（`entry.…`）を1か所（`src/services/feedback.ts`）にまとめる。フォームの設問は日本語・繁體中文・English を併記し、メールアドレスの収集はしない（返信がほしい人だけ、任意の欄に書く）。回答の通知は開発者のメールに届く。
- **URL が未設定のとき**：フォームの URL が空のビルドでは、フィードバックの部分だけを表示しない（版の表示は残す）。
- **文言**：3言語（ja・zh-TW・en）の共通の文言に追加する。
- **権利と出典の示し方（FR-SET-07〜10）**：
  - 設定画面には見出しと短い文だけを置き、出典の詳細とライブラリの一覧は「出典とライセンス」を押して開くダイアログ（`components/Dialog.tsx`）で示す。
  - ライブラリの一覧は、ビルドのときに `scripts/` のスクリプトで、実行時に使う依存パッケージ（`dependencies`）の名前・版・ライセンス・著作権表示を集めて `public/licenses.json` に書き出す（新しい依存パッケージは足さない）。ダイアログを開いたときに読み込み、初回表示には含めない（NFR-02）。オフラインでも開けるよう、事前キャッシュに含める（12.1）。
  - 出典の名前（中国語の部分）には `lang="zh-TW"` を付ける。外部のサイトへのリンクは FR-SET-05 と同じく新しいタブで開き、外部であることを示す。
- **リポジトリ側の表記（版 1.31）**：
  - リポジトリの直下に `LICENSE`（MIT License、著作権者「303tk4」）を置き、`package.json` の `license` を `MIT` とする。
  - 単語集（`public/packs/`）のうち開発者が作った部分（意味・例文・タグ）は CC BY 4.0、他者の素材（語の選定と級、注音）はそれぞれの出典の条件に従うことを、README と `public/packs/` の README に書く。
  - README に「ライセンス」「出典」「免責」の節を設け、アプリの「このアプリについて」と内容をそろえる。
- **本名の扱い**：著作権表示・LICENSE・README には GitHub のアカウント名だけを書き、本名・住所・メールアドレスは載せない。問い合わせの窓口は FR-SET-05 のフォーム（と GitHub の Issues）とする。有料化・広告の掲載・アプリストアでの配布を行う場合は、特定商取引法などによる表示が必要になるため、そのときに改めて検討する。

### 10.4 データの保護（バックアップ・復元・初期化）
データはこの端末のブラウザの中だけにあり（1.2）、機種変更・アプリの削除・ブラウザによる自動削除で失われうる。これに備えて、アプリ全体の状態を1つのファイルに保存し、そのファイルから元に戻せるようにする。あわせて、アプリを初期状態に戻せるようにする（版 1.32 で追加）。

設定画面の「データの保存」（12.1）の下に「バックアップと初期化」の欄を設け、上から「バックアップを保存」（FR-SET-11）、「バックアップから復元」（FR-SET-12）、「アプリを初期状態に戻す」（FR-SET-13）の順に置く。

| ID | 要件 |
|---|---|
| FR-SET-11 | 「バックアップを保存」で、単語・学習の進捗・学習の履歴・設定のすべてを1つの JSON ファイル（`tc-vocab-backup-YYYYMMDD-HHmm.json`）に書き出す。共有の機能（Web Share API でファイルを渡せる環境。主にスマートフォン）があれば、「共有して保存」も置き、Google ドライブ・メール・メッセージアプリなどに直接渡せるようにする |
| FR-SET-12 | 「バックアップから復元」で、FR-SET-11 のファイルを選び、確認のうえで、今のデータ（単語・学習の進捗・学習の履歴・設定）をファイルの内容にすべて置き換える。途中で失敗したら何も変えない |
| FR-SET-13 | 「アプリを初期状態に戻す」で、確認のうえで、単語・学習の進捗・学習の履歴・設定をすべて消し、初めて開いたときの状態に戻す |
| FR-SET-14 | 前回のバックアップから時間がたち、そのあとに単語や学習の記録が増えていれば、ホームでバックアップの保存を勧める（下記） |

- **ファイルの形式（FR-SET-11）**：
  - 9.1 の JSON 形式（`format: "tc-vocab"`、`version: 1`）に、`backup: true`、`appVersion`（書き出したアプリの版）、`sessions`（学習の履歴。6.3）、`settings`（設定の `{ key, value }` の配列。6.4）を加える。`words` は全単語、`progress` は全モードの進捗をすべて出力する（「学習進捗を含める」の選択は設けない）。
  - 単語・進捗の部分は 9.1 と同じなので、バックアップのファイルは単語の読み込み（9.3）でも使える（9.5 の往復の保証も同じ）。
  - `settings` には、この端末での案内の表示にだけ関わるキー（`app.installHintHidden`、`app.storageNoticeShown`、`app.backupReminderSnoozedUntil`、`app.lastBackupAt`）を含めない。それ以外（共通設定とモード別設定 `mode.<modeId>.*`）はすべて含める。
  - 書き出したら、その日時を設定 `app.lastBackupAt` に保存する（FR-SET-14 で使う）。共有を取りやめたときは保存しない。
  - 書き出しと共有は利用者の操作によるもので、アプリ自身は外部と通信しない（NFR-06）。
- **復元（FR-SET-12）**：
  - ファイルの選び方とサイズの上限は、単語の読み込みと同じ（FR-IO-01・07。JSON のみ）。
  - 次のときは置き換えず、理由を示す：`backup: true` が無い（単語の読み込みを案内する）、`version` がこのアプリより新しい（アプリの更新を案内する）、形式が正しくない、検証（6.1）でエラーのある単語が1語でもある（置き換えは全部か無しかとし、正しい単語だけを使う部分的な復元はしない）。存在しない単語の進捗は捨てる。
  - 確認のダイアログに、ファイルの書き出し日時と版、ファイルの件数（単語・進捗・履歴）と今の件数を示し、「今のデータはすべて置き換わり、元に戻せません」と示す。ボタンは「キャンセル」（初めに選ばれている）、「先に今のデータのバックアップを保存する」（FR-SET-11 を実行し、ダイアログは開いたまま）、「復元する」（危険の色）。
  - 置き換えは4つの表（`words`・`progress`・`sessions`・`settings`）をまとめた1つのトランザクションで行う（NFR-07）。ファイルに含めない端末のキー（FR-SET-11）は、この端末の値をそのまま残す。完了したら、`app.lastBackupAt` をファイルの書き出し日時とし、`localStorage` の表示設定の写し（10.1）を書き直し、`navigator.storage.persist()` を要求し（FR-PWA-04）、ホームを開き直す（画面の言語・背景の色などを反映するため、ページを読み込み直す）。
  - モードの進捗の形式は各モードが決める（6.2）ため、復元ではモードの状態の中身は検証しない。登録されていないモードの進捗と設定もそのまま戻す。
- **初期化（FR-SET-13）**：
  - ボタンは危険の色（`--color-danger`）とする。
  - 確認のダイアログの題は「アプリを初期状態に戻しますか？」とし、消える単語の数、学習の進捗・履歴と設定も消えること、元に戻せないことを示す。ボタンは「キャンセル」（初めに選ばれている）、「先にバックアップを保存する」（FR-SET-11 を実行し、ダイアログは開いたまま）、「初期状態に戻す」（危険の色）。
  - 4つの表を1つのトランザクションで空にし（データベース自体は消さない）、このアプリが `localStorage` に置いた値（表示設定の写し）を消してから、ホームを開き直す（ページを読み込み直す）。言語・背景の色などは初期値（10.1）に戻る。
  - オフライン用に保存したアプリ本体（Service Worker とそのキャッシュ）は消さない（データではなく、消すとオフラインで開けなくなるため）。
- **バックアップの勧め（FR-SET-14）**：
  - 基準の日時を、`app.lastBackupAt`、無ければ最も古い単語の `updatedAt` と最初の学習の履歴の `startedAt` の早い方とする。基準から30日以上たち、かつ基準より後に更新された単語か学習の履歴があるときに示す（バックアップを一度も保存していなければ、データがあるだけで示す）。
  - ホームの学習モードの一覧の下（FR-HOME-06 の案内の上）に小さなカードとして示し、「バックアップを保存」（FR-SET-11 をその場で実行）と「閉じる」を置く。「閉じる」を押したら30日間は示さない（`app.backupReminderSnoozedUntil`）。
  - 単語が0件のとき（FR-HOME-05 の案内を出しているとき）は示さない。
- **置き場所の理由**：単語データ画面の「ファイルに書き出す」（9.4）は単語の受け渡し（タグでの絞り込み、CSV）のためのものとし、アプリ全体の保存と復元は設定画面にまとめる。単語の読み込みの「上書きする」（FR-IO-03）は、同じ単語だけを置き換えてほかの単語や設定を残すもので、復元とは別とする。
- **実装**：バックアップの組み立てと検証は `io/backup.ts` の純粋な関数にして単体テストを書く（往復で全項目が戻ること、除くキー、各エラー）。置き換えと初期化のトランザクションは `db/repos/backup.ts` に置く。
- **確かめ方**：E2E で、単語を追加して学習し、設定を変えてからバックアップを保存し、初期化して単語が0件になること、そのファイルから復元すると単語・進捗・履歴・設定が戻ることを確かめる。

## 12. PWA・デプロイ仕様

### 12.1 PWA
| ID | 要件 |
|---|---|
| FR-PWA-01 | アプリ本体（HTML・JS・CSS・アイコン・サンプル単語）をキャッシュし、オフラインで全機能が動作する |
| FR-PWA-02 | ホーム画面にインストールできる。manifest には名前、アイコン（192px・512px・maskable）、`display: "standalone"`、`start_url: "./"` を設定する |
| FR-PWA-03 | 新しいバージョンを検出したら「更新があります」と通知し、利用者の操作で再読み込みする（`registerType: 'prompt'`）。学習セッション中は通知を保留する |
| FR-PWA-04 | データが残りにくい環境に備える（下記）。設定画面に、データの保存の状態（ブラウザによる自動削除から保護されているか）を表示する |
| FR-PWA-05 | ホーム画面への追加（パソコンではアプリとしてのインストール）を手助けする（下記）。M4.7 で実装する |
| FR-PWA-06 | データが保護されていない環境で、初めて単語を追加・編集したときに、データが消えうることと対策（ホーム画面への追加とバックアップ）を1回だけ知らせる（下記。版 1.32） |

データが残りにくい環境（プライベートブラウズ、終了時にサイトデータを消す設定、一部のアプリ内ブラウザ、しばらく開かないとデータを消す iPhone の Safari など）では、起動するたびに単語が0件になる。
- 「初回起動」はフラグや Cookie では判定せず、単語が0件かどうかで判定する（FR-HOME-05）。単語が消えた環境でも、案内は単語を追加する手段としてそのまま役に立つ。
- 案内はホーム画面に埋め込むカードとし、ポップアップにしない。閉じる操作や「次回から表示しない」は設けない（単語を追加すれば自然に消えるため、保存する状態が要らない）。
- 案内のカードの中に、どの環境で消えうるか（LINE などのアプリの中で開いた場合、ブラウザのシークレットモードで開いた場合）と、対策（Chrome などのブラウザで通常どおり開く。スマートフォンではホーム画面にこのアプリを追加し、パソコンではブラウザのメニューから「アプリとしてインストールする」を選ぶ）を、2つの段落に分けて小さく示す。「ホーム画面」は、アプリのホームではなく、利用者の機器のホーム画面であることがわかる書き方にする。
- `navigator.storage.persist()` は、単語を追加した時点（守るべきデータができた時点）で要求する。

補足（M4 で決定）：
- 事前キャッシュは HTML・JS・CSS・アイコン・`samples/` のサンプル単語とし、`packs/`（16.5 の単語パッケージ）は含めない。
- アイコンは favicon と同じ意匠（黒地 `#1c1c1c` に黄 `#ffd23f` の「詞」。字と背景のコントラスト比は約 12:1）とし、`public/icons/` に 192px・512px・maskable（512px、余白付き）と、iPhone 用の apple-touch-icon（180px）を置く。manifest の名前は「學中文 tc-vocab」、短い名前は「學中文」。
  - 字は端末の書体によらず同じ形に見えるよう、Noto Sans TC Bold（SIL Open Font License 1.1）の輪郭を `favicon.svg` に図形として収める。PNG は `node scripts/build-icons.mjs` で `favicon.svg` から作る（maskable は字を中心から半径 40% の円に収まるよう縮め、iPhone 用と maskable は角を丸めない）。
  - アイコンの色はアプリのボタンなどの色（FR-SET-04）とは別とし、manifest の `theme_color` は初期のボタンなどの色（赤）のままにする。
- 更新の通知（FR-PWA-03）は画面下部のバーとし、「再読み込み」と「あとで」を置く。「あとで」で閉じた通知は、次に起動したときに改めて出す。学習セッション中（モード画面のセッションの段階）は出さず、準備・結果やほかの画面に移ったら出す。開いたままでも気づけるよう、オンラインのときは1時間ごとに更新を確認する（確認先は公開元だけ。NFR-06）。
- 設定画面の「データ」に、保存の状態を「保護されています」「保護されていません」「このブラウザでは確認できません」のいずれかで示す（FR-PWA-04）。保護されていないときは、ホーム画面に追加すると保護されやすいことと、バックアップの保存（FR-SET-11。版 1.31 までは「ファイルに書き出す」）を案内する。保護を要求するボタンは設けない。

ホーム画面への追加の手助け（FR-PWA-05）：

| 環境 | 動作 |
|---|---|
| Android の Chrome・Edge・Samsung Internet、パソコンの Chrome・Edge | ブラウザが追加できることを知らせたとき（`beforeinstallprompt`）だけ、「ホーム画面に追加」（パソコンでは「アプリとしてインストール」）ボタンを示す。押すとブラウザの確認画面を出す |
| iPhone・iPad（Safari。iPhone の Chrome なども同じ） | ボタンから直接は追加できないため、「共有ボタン → 『ホーム画面に追加』」の手順を示す |
| LINE などのアプリの中のページ | ホーム画面には追加できないため、「Safari や Chrome で開き直してください」と示す。LINE では、外のブラウザで開くリンク（URL に `openExternalBrowser=1` を付ける）を置く |
| Firefox など、上のどれにも当たらないとき | 今の案内文（ブラウザのメニューから追加・インストールする）を示す |
| 追加済みのアプリとして開いているとき（`display-mode: standalone`、iOS の `navigator.standalone`） | ボタンも手順も示さない |

- 置き場所は、ホームの最初の案内（「対策」の段落）と、設定画面の「データの保存」。
- 環境の判定は端末の中だけで行い、外部とは通信しない（NFR-06）。User-Agent による判定は外れることがある（iPad がパソコンとして名乗るなど）ため、判定できないときは今の案内文に戻す。判定は React から切り離した純粋な関数にして単体テストを書く。

補足（M4.7 で決定）：
- 判定の区分は「追加済み」「iPhone・iPad」「LINE」「ほかのアプリの中」「Android」「パソコン」「判定できない」の7つ。iPadOS の Safari はパソコン（Macintosh）として名乗るため、Macintosh で画面に触れられる（`maxTouchPoints` が 2 以上）ものを iPad とみなす。iOS で User-Agent に `Safari/` を含まないものは、アプリの中の画面とみなす。
- `beforeinstallprompt` は描画より前（`main.tsx`）から受けて保持する。Android・パソコンでこの知らせが無いうちは、今の案内文を示す。`prompt()` は1回しか使えないため、断られたらボタンを消し、ブラウザがまた知らせてきたら出し直す。
- 追加し終えたとき（確認画面で追加された、または `appinstalled`）は、ボタンを消して「追加しました。次からはホーム画面のアイコンから開いてください。」（パソコンでは「インストールしました。次からはインストールしたアプリから開いてください。」）と示す。
- LINE 以外のアプリの中では、手順の文だけを示す（URL のコピーなどのボタンは置かない）。
- 設定画面の「データの保存」では、追加の案内を保護の状態にかかわらず示す。追加済みのアプリとして開いているときは、追加の案内の代わりに「ホーム画面に追加したアプリ（パソコンではインストールしたアプリ）として開いています。」と示す（版 1.19 で変更）。保存の勧め（版 1.32 からはバックアップの保存。FR-SET-11）は、これまでどおり保護されていないときだけ示す。

補足（版 1.19）：単語が1語以上あるときの、ホームでの追加の案内（FR-PWA-05）。単語が0件のときの最初の案内は、上のとおり。
- ホームの下部（学習モードの一覧の下）に、小さな案内のカードを置く。示すかどうかは環境で変える。

| 環境 | ホームの下部 |
|---|---|
| iPhone・iPad | 追加済みかを確かめる手段がなく、Safari がデータを消すおそれがあるため、共有ボタンからの手順を毎回示す。「今後表示しない」を置き、押されたら示さない |
| Android（Chrome・Edge・Samsung Internet など） | ブラウザが追加できると知らせているとき（`beforeinstallprompt`。追加済みなら知らせが来ない）だけ、「ホーム画面に追加」のボタンを示す。「今後表示しない」を置き、押されたら示さない。追加済みなら、「今後表示しない」が押されていなくても示さない |
| LINE・ほかのアプリの中 | データが消えやすいため、ブラウザで開き直す案内を毎回示す（LINE では外のブラウザで開くリンクも置く）。「今後表示しない」は置かない |
| パソコン、Android で知らせが来ないとき（Firefox など） | ブラウザのタブのまま使い続けたい利用者もいるため、示さない（単語0件の最初の案内と設定画面だけで示す） |
| 追加済みのアプリ・判定できないとき | 示さない |

- iPhone・iPad の案内には、追加を勧める理由（Safari には、しばらく開いていないサイトのデータを自動で消す仕組みがあること。目安は7日）を書く。単語が消えたときに、アプリの不具合と誤解されないようにするため。単語0件の最初の案内と設定画面でも同じ文面を使う。
- 「今後表示しない」は設定（`settings` テーブルのキー `app.installHintHidden`）に保存する。データが消された環境では保存も消えるため、案内がまた出る（データが消えうることを知らせる意味で、そのままでよい）。設定画面の「データの保存」の案内は、この設定にかかわらず示す。

データが消えうることの知らせ（FR-PWA-06。版 1.32）：
- 編集のたびに警告を出すと煩わしく、読まれなくなるため、知らせるのは1回だけとする。
- 示す条件：単語の追加・編集・読み込み・単語集の追加が成功し、`navigator.storage.persist()` を要求した（FR-PWA-04）あとで、次のすべてに当てはまるとき。
  - 保存の状態が「保護されています」でない（「保護されていません」か「このブラウザでは確認できません」）。
  - 追加済みのアプリとして開いていない（FR-PWA-05 の判定）。
  - まだ知らせていない（`settings` テーブルのキー `app.storageNoticeShown` が無い）。
- 示し方：画面下部のバー（更新の通知 FR-PWA-03 と同じ形）に、「このアプリのデータはブラウザの中に保存されていて、ブラウザが消すことがあります。ホーム画面に追加し、ときどきバックアップを保存してください。」という趣旨を示し、「詳しく」（設定画面の「データの保存」を開く）と「閉じる」を置く。
- 示した時点で `app.storageNoticeShown` を保存し、どちらのボタンを押しても、押さずに画面を移っても、二度と示さない。データが消された環境では保存も消えるため、また示す（それでよい）。
- 学習セッション中は示さない。更新の通知が出ているときは、それが閉じてから示す。

### 16.3 単語の個別追加・編集の実装方針
インポートを使わずに、アプリの中で単語を1語ずつ追加・編集できるようにする。実装に入る前に、要件 ID を付けて 4.5 に追記する。

| 項目 | 方針 |
|---|---|
| 入口 | 単語データ画面に「単語を追加」ボタンを置く。一覧の各行と暗記カードの裏面から、その単語の編集を開く（暗記カードからは `CoreServices` に編集用の API を足す） |
| 入力画面 | ダイアログ（`components/WordEditDialog.tsx`）。繁体字・意味（必須）、注音、拼音、例文と訳（追加・削除、10件まで）、タグ（`TagField` を使う）。続けて追加できるよう「保存して次へ」を置く |
| 検証 | インポートと同じ `io/validate.ts` の `normalizeWord` を使い、6.1 の制約をそのまま当てる。エラーは項目の下に示す |
| 重複 | 繁体字と拼音が同じ単語があれば保存前に知らせ、「既存の単語を開く」「このまま追加する」を選べる（6.1 の重複の判定と同じ規則） |
| 保存 | `db/repos/words.ts` に `addWord`・`updateWord` を追加する。編集では `updatedAt` だけを更新し、学習進捗は変えない |
| 読みの入力補助 | 拼音と注音は音節の対応表（約400音節）で相互に変換できるため、片方を入れるともう片方を候補として示す。繁体字から読みを自動で付けるには辞書データ（教育部《國語辭典》など）が必要で、容量とライセンスの確認が要るため、別途検討する |
| 音声 | 単語ごとの音声ファイルは持たない。読み上げは端末の音声合成（Web Speech API、`zh-TW` の音声）が繁体字の文字列からその場で行うため、アプリ内で追加した単語も追加の作業なしで読み上げられる。ただし、多音字の読み分けは音声合成に任せることになり、拼音の通りに読ませることはできない。自分の声を録音して単語に付ける機能は、容量・エクスポート形式への影響が大きいため、必要になったら別途検討する |


### 16.4 注音・拼音の自動付与
声調記号つきの拼音や注音は、利用者が自分で入力するのが難しい。インポート後や単語の追加時に、アプリが読みを付けられるようにする。2段階に分けて進める。

**段階1：入力の補助（辞書データ不要。16.3 と同時に行う）**

| 項目 | 方針 |
|---|---|
| 数字の声調 | `jie2 yun4`・`jie2yun4` のような数字つき拼音を受け付け、声調記号つき（`jié yùn`）に直す。インポートと単語の追加の両方で行う |
| 拼音と注音の変換 | 音節の対応表（約400音節、数 KB）で相互に変換する。単語の追加・編集の画面で、片方だけが入力されていれば、もう片方を自動で埋める（FR-WORDS-18）。インポートでは自動で埋めない（取り込む内容が大きく変わるため。版 1.16 で決定） |
| 実装 | 数字の声調の変換は `io/validate.ts` の `normalizeWord` で行い、インポートと単語の追加・編集の両方に効かせる。変換は `io/reading.ts` に集約する（単語パッケージを作るスクリプトの `scripts/packs/lib/zhuyin.mjs` と同じ規則） |

**段階2：繁体字からの自動付与（将来）**

| 項目 | 方針 |
|---|---|
| 操作 | インポートのプレビューと単語の一覧で「読みが空の単語に読みを付ける」を選べる。付けた読みは確定前に一覧で確認・修正できる |
| 仕組み | 辞書データ（単語とその読み）を、使うときだけ読み込む。長い単語から順に一致させ（最長一致）、辞書にない部分は1字ずつ読みを引く |
| 多音字 | 「行」（háng / xíng）、「長」（cháng / zhǎng）のように読みが複数ある字は、単語として辞書にあれば正しく付く。1字だけで判定する場合や辞書にない語は、もっともよく使われる読みを付け、タグ `要確認:読み` を付ける（タグで絞り込んで確認できる） |
| 辞書データ | 教育部《重編國語辭典修訂本》から、見出し語と注音だけを抜き出して使う（決定。規約上の問題はないものとして進める）。ビルド時のスクリプトで `public/dict/zhuyin.json` を作り、拼音は注音から音節の対応表で変換する（辞書の拼音は使わない） |
| 出典の表示 | 設定画面に、注音の出典（教育部《重編國語辭典修訂本》）とライセンス（創用CC 姓名標示-禁止改作 3.0 臺灣）を示す（FR-SET-08。版 1.31） |

段階2の課題：

| 課題 | 内容 |
|---|---|
| データの入手 | 教育部の公眾授權網から辞典のデータファイルをダウンロードする。ダウンロードは実装を始めるときに利用者の承認を得て行う |
| 容量 | 単語数万語分の辞書は数 MB になる。初回表示には含めず（NFR-02）、読みを付ける操作をしたときに読み込む。オフラインで使うには、読み込んだデータを端末に保存する |
| 正確さ | 自動で付けた読みは誤ることがある（多音字、固有名詞、新語）。必ず利用者が確認できるようにし、確認前の読みは区別して示す |
| 読み上げとの関係 | 音声合成（[16.3](#163-単語の個別追加編集の実装方針)）は拼音を参照しないため、付けた読みが正しくても読み上げの多音字の誤りは直らない |

### 16.5 単語パッケージ
アプリの操作だけで、目的別の単語のまとまり（例：ネットスラング、コンピュータ用語、旅行会話）を追加できるようにする。

| 項目 | 方針 |
|---|---|
| 配布場所 | アプリと同じ GitHub Pages の `public/packs/` に置く。一覧 `index.json`（ID・名前・説明・単語数・版・ライセンス）と、パッケージごとの JSON（9.1 の形式）。同じサイト内のファイルを読むだけなので、外部への通信をしない方針（NFR-06）に反しない。サンプル単語（11章）と同じ仕組み |
| 画面 | 単語データ画面のツールバーに「単語パッケージ」を置く。ボタンは「単語を追加」「単語集を読み込む」（英語では「Add from word packs」）「ファイルを読み込んで単語を追加」の順とする（自分のファイルを持たない利用者が多いため、単語集を先に勧める。版 1.30）（「サンプル単語を追加」はこれに置き換え、サンプル単語は一覧の先頭に示す。FR-SMP-04）。一覧から選ぶと、単語数・容量・数語の見本を示し、インポートと同じプレビュー（新規・重複の件数）を経て追加する。ホームの案内からは、単語データ画面を開いて一覧を表示する（`#/words?open=packs`） |
| 最初の案内 | 単語が0件のときのホーム画面の案内（FR-HOME-05）を「単語を追加して始めましょう」とし、次の3つを並べる。(1) 単語パッケージを選ぶ（TOCFL・HSK などの目的別の単語集を選んですぐに学習を始められることを示す） (2) サンプル単語を追加（約50語、通信不要） (3) 自分のファイルをインポート |
| 通信と容量の表示 | 単語パッケージの一覧と各パッケージに、ダウンロードにインターネット接続が必要なことと、ダウンロードの容量（例：「約 1.2 MB」。index.json に記録する）を示す。オフラインのときは「インターネットに接続すると選べます」と示し、サンプル単語とインポートは使えるようにする |
| タグ | 追加した単語には、パッケージで決めたタグ（例：`HSK5`、`TOCFL:進階` と `TBCL:4級`）を自動で付ける。試験の名前だけのタグ（`TOCFL`・`HSK`）は、分類として大きすぎるため付けない（版 1.28）。不要になったら、そのタグで絞り込んで全選択し、削除できる（FR-WORDS-05） |
| 重複 | 既にある単語（6.1）は、初期値では「タグだけ付ける」とする。既存の単語の意味・例文・読み・学習進捗は変えず、パッケージのタグだけを加える。1つの単語が複数の単語集に入っていれば、タグが増えていく（例：`HSK4` と `TOCFL:進階`）。タグが上限（20件）を超える単語は変更せず、件数を示す。ほかに、FR-IO-03 と同じ「統合する」「重複分もインポートする」「インポートしない」も選べる。「タグだけ付ける」はパッケージでだけ選べる（ファイルのインポートでは選べない）。サンプル単語の扱いは FR-SMP-04 による |
| 更新 | 追加したパッケージの ID と版を `settings` テーブルのキー `packs.installed` に記録し、一覧に「追加済み」と示す。パッケージの版が上がったら一覧に「更新あり」と示す。更新では、新しく加わった単語を追加し、既にある単語にはタグだけを付ける。パッケージ側で直した内容（意味の修正など）は、利用者が編集した内容を上書きしないよう自動では反映しない。変更点を示して反映できるようにするかは、作るときに決める |
| 追加済みの判断と再追加 | 「追加済み」は記録だけでなく、実際に登録されている単語で判断する。単語集の `presenceTags`（無ければ `tags`）のどれかが付いた単語が1語も無ければ「追加済み」を示さない（利用者が単語を消した場合など）。一部だけ残っていれば「追加済み（1,375 語のうち 800 語が登録中）」のように示す。サンプル単語は `sample` タグの単語があれば「追加済み」とする。追加済みでも一覧に残し、ボタンを「もう一度追加する」（新しい版があれば「更新する」）として、何度でも選べるようにする（消した単語の追加し直しや、元の内容への復元のため）。追加済みの項目では、ボタンの下に「もう一度追加しても、学習の進捗は消えません」と示す |
| 単語集の内容に戻す | 重複の扱いに「単語集の内容に戻す」（上書き）を加える。登録済みの単語の意味・読み・例文・タグを単語集の元の内容に置き換え、学習の進捗は残す。利用者が直した内容や付けたタグは失われるため、実行前に件数を示して確認する。サンプル単語では選べない（FR-SMP-04） |
| 意味の言語 | 単語集の意味・例文の訳は1つの言語で書き、言語ごとに別の単語集とする（例：`tocfl-1`（日本語）、`tocfl-1-vi`（ベトナム語））。単語のデータの形（`meaning` は1つ）は変えない。`index.json` の `meaningLanguage` に意味の言語を書き、一覧と各単語集に「単語の意味の表記：Tiếng Việt」のように示す（「意味：」だけでは何を指すかわかりにくいため「単語の意味の表記」とする。版 1.29）。言語名はボタンなどの色（`--color-accent-strong`）の太字で目立たせる（版 1.30）（言語名はその言語自身での名前。「意味：」は UI 言語の文言。`meaningLanguage` の無い単語集は示さない）。一覧では、UI 言語と同じ意味の言語の単語集を先に並べる（言語は主な部分で比べ、`en-US` と `en` は同じとする）。UI 言語に合う単語集が無いとき（UI が繁體中文のときなど）は、英語の単語集を先に並べる。どちらの場合も、先に並べるもの以外と、同じ言語の中は `index.json` の順とする（版 1.27 で、合う単語集が無いときの案内を、英語を先に並べることに改めた）。同じ内容の言語違いの単語集は、級などのタグを共通にする（どの言語版を追加しても、同じタグで絞り込める）。別の言語版を追加すると、既にある単語は初期値の「タグだけ付ける」で意味が変わらない。意味を別の言語に置き換えたいときは「単語集の内容に戻す」を使う（版 1.22） |
| オフライン | 一覧とパッケージは使うときに読み込む。初回表示や PWA の事前キャッシュには含めない（M4） |
| 一覧の形式 | 下記の `index.json`。各パッケージの単語は 9.1 の JSON 形式とし、単語ごとに級などのタグ（例：`TOCFL:入門`・`TBCL:1級`）を入れておく |
| 作成と審査 | パッケージはリポジトリに JSON を追加して作る。読み（16.4）・意味・例文の確認と、出典のライセンスの確認を経てから公開する |
| 対象外 | 任意の URL から外部のパッケージを読み込む機能は作らない（NFR-06 と、内容の安全性を確かめられないため）。個人どうしの共有は、JSON ファイルのエクスポート・インポートで行う |

一覧 `public/packs/index.json` の形式：
```json
{
  "format": "tc-vocab-packs",
  "version": 1,
  "packs": [
    {
      "id": "tocfl-novice",
      "file": "tocfl-novice.json",
      "version": 1,
      "name": { "ja": "TOCFL 入門・基礎", "zh-TW": "TOCFL 入門・基礎", "en": "TOCFL Novice" },
      "description": { "ja": "華語文能力測驗の入門・基礎の単語。単語の意味や例文（例文がある場合）には、AI により生成されたものが多数含まれています。", "zh-TW": "…", "en": "…" },
      "wordCount": 1000,
      "size": 245760,
      "tags": ["TOCFL:入門", "TOCFL:基礎"],
      "presenceTags": ["TBCL:1級", "TBCL:2級", "TBCL:3級"],
      "meaningLanguage": "ja",
      "license": "…",
      "source": "…"
    }
  ]
}
```
- `id` は `^[a-z0-9][a-z0-9-]*$`。追加済みの記録に使うので、公開後は変えない。`file` は `packs/` からの相対パス。`version` は内容を変えるたびに 1 増やす整数。
- `name`・`description` は言語ごとの文字列。`name` は UI 言語で示し、無い言語は `ja`、次に最初の項目で代用する。`description` は UI 言語によらず、その単語集の意味の言語（`meaningLanguage`）の文で示し、`lang` 属性を付ける（例：英語の単語集の説明は、UI 言語が日本語でも英語で示す。説明文の言語で、どの言語の単語集かがひと目でわかるようにするため。版 1.29）。単語集を作るときは、`description` に必ず意味の言語の文を入れる。意味の言語の文が無いときだけ、`name` と同じ順で代用する。級の対応表（`levelGuide`）と「出典とライセンス」は、単語集の中身ではなく試験や出典の説明なので、UI 言語で示す。`size` はパッケージの JSON のバイト数（容量の表示に使う）。`tags` は一覧に示すタグ（実際に付くタグは単語ごとの `tags`）。
- `format` や `version` が想定と違う一覧、形式の誤ったパッケージは読み込まず、その旨を示す。サンプル単語はこの一覧に含めず、アプリが一覧の先頭に加える。
- 任意の項目 `presenceTags` に、「追加済み」の判断に使うタグを書ける。単語集どうしで重ならないタグ（例：TOCFL の単語集では TBCL の級のタグ `TBCL:5級`）を指定する。一覧に示す `tags` は、試験の級（例：`TOCFL:高階`）が複数の単語集で重なることがあり、判断に使うと、ほかの単語集の単語まで数えてしまうため。無ければ `tags` で判断する。同じ級の意味の言語ちがいの版（例：`tocfl-3` と `tocfl-3-en`）は単語が同じなので、同じタグでよい（版 1.28）
- 任意の項目 `levelGuide` に、試験の級の対応表（例：TOCFL の各級に相当する TBCL の級）を書ける。`title`・`note` と、列 `columns`（`tocfl`・`cefr`・`listening`・`reading`）の見出しは UI 言語ごとの文字列。`rows[]` の各行は `{ tocfl, cefr, listening, reading, inPack, tag? }`（`tocfl` は UI 言語ごとの文字列、`inPack` はこのパッケージに収めている級か、`tag` はその級の単語に付けるタグ）。`source` は出典（`name` と `url`）。形式の誤った対応表は表示しないだけで、パッケージは使える。
- このほかの項目（`updatedAt`・`meaningNote`・`tagCounts`・`sources` など）は、アプリは読まずに無視する。
- 一覧では、各パッケージに `tags` を示し、対象の試験と級がわかるようにする（例：`TOCFL:入門`・`TOCFL:基礎`）。選んだあとのプレビューでは、`levelGuide` があれば対応表を示し（収めている級の行を目立たせる）、`source` と `license` を「出典とライセンス」として示す。

主な課題は技術よりも内容にある。単語・意味・例文の作成と校閲の手間、辞書やウェブから集める場合の著作権、意味を何語で書くかは、言語ごとに別の単語集とすることに決めた（上の「意味の言語」。版 1.22）。

サンプル単語（11章）はアプリに同梱し、TOCFL・HSK などの単語集は事前に入れずに単語パッケージとして配る（決定）。使わない単語で一覧や出題がふさがらないこと、目的（台湾の TOCFL か中国大陸の HSK か）で選べること、パッケージごとに更新できることによる。

TOCFL・HSK の単語集の作り方（公式の語彙表は公開されており、単語集として配ってよいものとして進める。決定）：

| 手順 | 担当 | 方針 |
|---|---|---|
| 語彙表の入手 | Claude | 公式サイトから語彙表を入手する。元のファイルは \`scripts/packs/sources/\` に置き、出典と入手日を記録する。ダウンロードは利用者の承認を得て行う |
| 繁体字への変換（HSK） | スクリプト | HSK の語彙表は簡体字のため、台湾の字形・語彙への変換表（OpenCC の簡体字→台湾正體など、再配布できるもの）で繁体字にする。変換が一意に決まらない語は一覧にして確認する |
| 注音・拼音 | スクリプト | 教育部《重編國語辭典修訂本》の注音（16.4）で付け、拼音は注音から変換する。辞書にない語は \`要確認:読み\` タグを付ける |
| 日本語の意味 | Claude | 数百語ずつ下書きする。パッケージの説明に「単語の意味や例文（例文がある場合）には、AI により生成されたものが多数含まれています」と示す（AI 以外による意味や例文が加わることもあるため、すべてが AI によるとは書かない）。読みの `要確認:読み` の説明は、追加前の確認画面（FR-WORDS-14）に任せ、説明には書かない |
| ほかの言語の意味 | Claude | ベトナム語・韓国語・インドネシア語などの単語集では、意味と例文の訳を、日本語の訳からではなく繁体字の単語から直接その言語で下書きする（訳を重ねて意味がずれるのを避ける）。説明には同じ趣旨を示す |
| 確認 | 利用者 | 抜き取りで確認してから公開する |
| タグと版 | スクリプト | 級ごとのタグ（例：\`TOCFL:入門\`・\`TBCL:1級\`、\`HSK5\`）を付け、\`public/packs/\` に版つきで出力する |

- 量が多いため（TOCFL は約8千語、新しい HSK は1〜9級で1万語を超える）、まず TOCFL の入門・基礎（約1千語）で試し、品質と手順を確かめてから広げる。
- 変換と出力のスクリプトは \`scripts/packs/\` に置き、語彙表の更新時に作り直せるようにする。

### 16.6 簡体字の併記
繁体字を学ぶ人が簡体字も見られるよう、また簡体字に慣れた人が使えるよう、字体の表示を選べるようにする（将来）。

| 項目 | 方針 |
|---|---|
| 設定 | 共通設定（10.1）に「字体の表示」を追加する。「繁体字のみ」（初期値）、「繁体字＋簡体字」、「簡体字＋繁体字」、「簡体字のみ」 |
| 併記の見た目 | 主に表示する字体のすぐ横に、もう一方を少し小さく（約 0.6 倍）、薄い色（\`--color-muted\`）で表示する。両方が同じ字（例：「人」「水」）のときは併記しない |
| 対象 | 単語データ画面の一覧、暗記カードの表面・裏面、例文。学習モードには、コアが字体を変換する関数を \`CoreServices\` で渡す |
| データ | 正本は繁体字（\`hanzi\`）のままとし、検索・重複の判定・並べ替えは繁体字で行う。簡体字は表示のたびに変換表（OpenCC の繁体字→簡体字など）で作る。変換表は、この設定を選んだときだけ読み込む（NFR-02） |
| 個別の指定 | 変換で正しくならない語のために、将来、単語に簡体字の項目（任意）を設け、CSV の列 \`simplified\` で指定できるようにすることを検討する |
| 検索 | 併記を選んでいるときは、簡体字でも検索できるようにする |
| 言語の指定 | 簡体字の部分には \`lang="zh-CN"\`（またはzh-Hans）を付け、フォントは \`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif\` の順で指定する（NFR-04・05） |
| 読み・読み上げ | 「簡体字のみ」でも、読み（注音・拼音）と読み上げは台湾の規範のままとする |

### 16.8 UI 言語の追加
将来の構想（未決定）。画面の表示言語（FR-SET-01）を、日本語・繁體中文・English のほかにも選べるようにする。単語の「意味」欄の言語とは関係しない（10.1）。

| 項目 | 方針 |
|---|---|
| 候補 | ベトナム語（Tiếng Việt、`vi`）、インドネシア語（Bahasa Indonesia、`id`）、ロシア語（Русский、`ru`）、フランス語（Français、`fr`）、スペイン語（Español、`es`）、タイ語（ไทย、`th`）、韓国語（한국어、`ko`）。設定の選択肢には、各言語の名前をその言語で示す |
| 優先順位 | ベトナム語 → 韓国語 → インドネシア語を先に追加する（版 1.22）。ロシア語・フランス語・スペイン語・タイ語はその後とする。1言語ずつ、確認できる人がいる言語から足してよい |
| 単語集 | 優先する3言語では、UI の翻訳とあわせて、少なくとも TOCFL 単語集（TBCL 第1〜3級）を、意味と例文の訳までその言語で用意する（16.5 の「意味の言語」）。利用者が取り込んだ単語の意味は翻訳しない（16.1 の決定 6） |
| 言語の判定 | FR-SET-01 の初期値の判定に、追加した言語を加える（例：`ko*` → 한국어）。どれにも当たらなければ、これまでどおり English |
| 文言の追加 | 共通の文言（`src/i18n/locales/`）と、各モードの `locales/` に、同じキーで言語のファイルを足す。`locales.test.ts` はすべての言語でキーがそろっていることを確かめる。単語パッケージの `name`・`description`・`levelGuide` など、UI 言語ごとの文字列は、無い言語では 16.5 のとおり `ja`、次に最初の項目で代用する（English を先にするかは追加時に決める） |
| 初回表示の大きさ（NFR-02） | 現在は3言語の文言をすべて初回の JS に含めている。言語を増やすときは、選んだ言語の文言だけを動的 `import()` で読み込む形に変え、オフラインでも切り替えられるよう、すべての言語を事前キャッシュに含める（12.1） |
| 複数形・書式 | ロシア語などは数による語形の変化が多いため、i18next の複数形（`_one`・`_few`・`_many` など）を使う。日付・数の表示は `Intl` で言語に合わせる |
| 表示 | 文言が長くなりやすい言語（ロシア語・フランス語など）でも、ボタンや見出しが崩れず、横スクロールが出ないことを確かめる。タイ語・韓国語の部分にはその言語の `lang` を付け、端末のフォントで表示する（外部のフォントは読み込まない。NFR-06） |
| 翻訳の品質 | 下書きは Claude が作り、その言語を使う人に見てもらってから公開する。中国語の学習用語（注音、声調など）の訳語をそろえる。単語集の意味と例文の訳も同じく確認を経る |
